# pi-agent 项目升级计划

> 基于 DeepSeek Harness 架构理念的全面升级方案
> 版本: 2.0 | 更新日期: 2026-08-19

## 一、项目目标

### 1.1 核心目标
- **对标 DSH 架构**：借鉴 DSH 的 5 个核心设计理念（观察、配置、隔离、追溯、组合）
- **提升开发效率**：构建速度提升 5 倍，热重载支持插件开发
- **增强可观测性**：完整的事件追踪系统，支持时间线可视化
- **改善用户体验**：长对话流畅、工具调用可视化、思考过程可追溯

## 三、详细任务清单

### 3.1 包拆分 (M11)

**目标：** 将当前 3 个包拆分为 10+ 个独立包

**新包结构：**
```
packages/
├── core/              # 核心类型和接口
├── agent/             # Agent 运行时
├── session/           # 会话管理
├── tracer/            # 追踪系统
├── plugin/            # 插件系统
├── tools/             # 工具注册表
├── protocol/          # AG-UI 协议
├── shared/            # 共享工具
├── config/            # 配置管理
└── test-support/      # 测试工具
```

**子任务：**
- [ ] 创建各包目录和 `package.json`
- [ ] 移动源码并更新 import 路径
- [ ] 配置 `tsdown.config.ts` 和 `tsconfig.json`
- [ ] 更新根目录 `pnpm-workspace.yaml`
- [ ] 验证 `pnpm build` 正常

**验收标准：**
- `pnpm build` 成功
- 各包可以独立发布
- 无循环依赖

---

### 3.2 foldSurface UI 集成 (M12)

**目标：** 用户编辑消息时，旧消息不被覆盖，可通过“查看历史版本”追溯

**子任务：**
- [ ] 前端调用 `GET /api/traces/:traceId/surface` 获取当前表面
- [ ] 消息列表根据 `surface` 事件渲染
- [ ] 添加“查看历史版本”按钮
- [ ] 弹出对话框显示版本链

**API 端点（已实现）：**
```
GET  /api/traces/:traceId/surface          # 获取当前表面
GET  /api/traces/:traceId/trace-event/:seq # 追踪事件关系
```

**验收标准：**
- 编辑消息后，旧消息可通过“历史版本”查看
- 版本链显示完整
- 无性能退化

---

### 3.3 预设继承/覆盖 (M13)

**目标：** 支持预设组合和覆盖

**配置文件格式：**
```yaml
# config/plugins.yml
presets:
  base:
    plugins:
      - id: novel-plugin
        enabled: true

  advanced:
    extends: base
    plugins:
      - id: web-search-plugin
        enabled: true
      - id: novel-plugin
        config:
          maxChapters: 200
```

**子任务：**
- [ ] 实现 `extends` 字段解析
- [ ] 实现配置合并（深度合并）
- [ ] 实现配置覆盖
- [ ] 添加单元测试

**验收标准：**
- 预设继承正常工作
- 配置合并正确
- 覆盖优先级符合预期

---

### 3.4 E2E 测试 (M14)

**目标：** 建立核心流程自动化测试

**技术选型：** Vitest + Playwright

**测试范围：**
- 创建项目 → 生成章节 → 保存 → 查看追踪
- 插件加载 → 服务注册 → 工具调用
- UI 交互：消息发送 → 流式响应 → 工具调用卡片

**子任务：**
- [ ] 安装和配置 Playwright
- [ ] 编写核心流程测试
- [ ] 编写 UI 交互测试
- [ ] 集成到 CI

**验收标准：**
- 核心流程测试通过
- UI 交互测试通过
- CI 集成成功

---

### 3.5 日志导出 UI (M15)

**目标：** 导出追踪报告为 HTML/JSON

**参考 DSH：** `session-log-export`

**子任务：**
- [ ] 在诊断弹框中添加“导出”按钮
- [ ] 调用 `POST /api/traces/export` 生成报告
- [ ] 下载为 HTML 文件
- [ ] 报告包含时间线、事件详情、耗时统计

**验收标准：**
- 导出按钮正常工作
- HTML 报告可打开
- 报告内容完整

---

### 3.6 双面构建 (M16)

**目标：** 同一份代码生成服务端/客户端产物

**子任务：**
- [ ] 配置 `tsdown` 支持 `DSH_BUILD_FACE` 环境变量
- [ ] 条件编译区分服务端/客户端
- [ ] 更新构建脚本

**验收标准：**
- 服务端产物不含客户端专用代码
- 客户端产物不含服务端专用代码
- 构建速度无退化
