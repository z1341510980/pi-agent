# Pi-Agent 前端优化改版方案（修订版）

## 一、现状诊断

### 核心问题

**信息密度过载，视觉层级扁平。** 当前 Novel Workspace 在 1440px 屏幕上同时展示 5 个面板（左侧栏 240px + 主编辑区 + 矩阵区 + 右侧栏 420px），每个面板内部还有多层嵌套（Tab 栏 + 状态栏 + 内容区 + 输入区）。用户的注意力被均匀分散，没有明确的"当前焦点"。

**具体表现：**

- 右侧 420px 面板承载了对话/详情/审计/扫描 4 个完整功能，每个功能内部又有子 Tab（工作流/群聊/反推/矩阵编排/聊天），形成"Tab 套 Tab"的嵌套结构
- 矩阵视图（16 个组件文件）信息密度极高但缺乏渐进式展示——所有实体的所有维度同时可见
- 主编辑区和矩阵区上下分割，两者都需要大视野，互相挤压
- 左侧栏（章节树 + 大纲）和右侧栏同时展开时，主内容区仅剩约 700px，对写作场景偏窄
- 流程 Tab 在窄面板下被压缩变形（已修复为图标模式，但根本问题是功能堆叠）

### 设计系统现状

| 维度 | 现状 | 评价 |
|------|------|------|
| 色彩 | TRAE Work 风格，紫色主色 #4b3fe3，中性灰体系 | 基础扎实，但语义色使用不一致 |
| 字体 | SF Pro / PingFang，14px 基准，-0.02em 字距 | 缺少明确的 Type Scale（标题/正文/辅助文字层级） |
| 圆角 | 4/6/8/10px 四级 | 存在但未按嵌套规则使用（同心圆角） |
| 阴影 | 极少使用，主要靠 border 分隔 | 导致界面扁平，层级感弱 |
| 动效 | framer-motion 已引入，但使用零散 | 缺少统一的动效语言（进入/退出/状态切换） |
| 间距 | 无明确 spacing scale 约束 | 各组件间距不一致（px-2 / px-2.5 / px-3 混用） |

### 已有技术基础

以下能力已具备，改版不需要重新建设：

- 横纵虚拟化（矩阵已实现行/列可视窗口计算）
- 实体展开子轨道（matrix-subtracks.tsx）
- 搜索过滤、Ctrl+滚轮缩放、多选与拖拽操作
- framer-motion + AnimatePresence（面板切换动画已有）
- zustand persist + localStorage（矩阵侧栏折叠、视图模式已持久化）
- react-hotkeys-hook（矩阵已使用）
- @tanstack/react-virtual（已安装）
- prefers-reduced-motion 支持（main.css 已实现）

## 二、改版范围边界

**本次聚焦小说工作台，不涉及其他页面。**

纳入范围：
- 小说工作台布局（novel-workspace.tsx 及其子组件）
- 编辑器、矩阵、右侧对话面板
- 共享 UI 基础组件（button、input、tabs、dialog、resizable-splitter）
- 工作台内快捷键和反馈机制
- 设计 token 扩展（main.css 变量）

不纳入范围（后置处理）：
- 设置页、首页、用量页、Agent 管理页
- 聊天工作台（chat-workspace.tsx）——布局模式类似但独立迭代
- 后端 API 变更
- 数据模型/存储结构变更

## 三、布局重构

### 3.1 从"五面板并列"到"焦点模式 + 辅助侧栏"

**核心思路：** 任何时刻只有一个主焦点区域，其余功能通过可收起的侧栏/抽屉提供。

```
┌─────────────────────────────────────────────────────────────────┐
│  Nav Rail (48px)                                                │
│  ┌───────────────────────────────────────────────────────────┐  │
│  │                                                           │  │
│  │  ┌─ 左侧栏（可折叠）─┐  ┌── 主工作区 ──────────────────┐  │  │
│  │  │                   │  │                              │  │  │
│  │  │  章节树           │  │  根据模式切换：              │  │  │
│  │  │  大纲             │  │  · 写作模式：编辑器全宽      │  │  │
│  │  │  实体快览         │  │  · 矩阵模式：矩阵全宽        │  │  │
│  │  │                   │  │  · 分屏模式：编辑+矩阵       │  │  │
│  │  │  宽度: 220px      │  │                              │  │  │
│  │  │  折叠后: 0px      │  │  宽度: flex-1               │  │  │
│  │  └───────────────────┘  └──────────────────────────────┘  │  │
│  │                                                           │  │
│  │  ┌─ 右侧面板（非模态侧滑/停靠）─────────────────────────┐ │  │
│  │  │  对话 / 详情 / 审计                                   │ │  │
│  │  │  宽度: 340px（停靠）/ 380px（侧滑后主区同步腾位）    │ │  │
│  │  └───────────────────────────────────────────────────────┘ │  │
│  └───────────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────────┘
```

**关键改动：**

1. **主工作区模式切换**（替代当前的上下分割）：
   - 写作模式：编辑器占满主区域，矩阵通过底部抽屉或新标签页访问
   - 矩阵模式：矩阵占满主区域，编辑器通过点击章节行内联展开
   - 分屏模式：保留当前上下分割，但默认比例改为 40:60（矩阵更大）

2. **右侧面板：非模态侧滑 + 停靠策略**（修订：不使用遮罩浮层）：
   - 默认关闭。打开时，面板以 `transform: translateX` 从右侧进入；同时工作区通过 `grid-template-columns` 或主区右侧内边距，在同一动画时长内腾出面板宽度。面板不使用遮罩，也不覆盖编辑器、矩阵或其交互区域
   - 侧滑模式：面板宽度 380px，作为临时打开方式；关闭后主区恢复全宽
   - 停靠模式：用户可固定为 340px 常驻栏；与侧滑模式最终布局一致，仅默认状态和进入方式不同
   - 创作流程运行时：自动切换为停靠模式（用户需要同时观察正文、矩阵和对话）
   - 用户可在运行中手动关闭右栏，但保留明显的运行状态入口（如主区域右上角的脉冲指示器）
   - 详情、审计、扫描：优先使用非模态抽屉或停靠栏
   - 仅删除、覆盖、不可逆操作使用模态 Dialog

3. **左侧栏增加折叠能力**：
   - 折叠为 0px（不是图标模式，直接隐藏）
   - 通过快捷键 `Cmd/Ctrl+B` 切换
   - 折叠时章节导航通过主区域顶部的面包屑替代

### 3.2 右侧面板内部重构

**当前问题：** 对话面板内部有 5 个流程 Tab + 状态栏 + 消息流 + 输入框，在 380px 宽度内极度拥挤。

**改为分级入口结构**（修订：不全部改为 Select）：

```
┌─ 右侧面板 ─────────────────────┐
│ ┌─ 顶部：视图切换 ───────────┐ │
│ │  对话  |  详情  |  审计    │ │  ← 保留，改为图标+文字胶囊
│ └────────────────────────────┘ │
│                                │
│ ┌─ 对话视图 ─────────────────┐ │
│ │ ┌─ 创作方式 ────────────┐  │ │
│ │ │ [工作流] [聊天]  ···  │  │ │  ← 高频模式常驻 Segmented
│ │ └───────────────────────┘  │ │     低频收进 ··· Popover
│ │                            │ │
│ │  消息流（flex-1 滚动区）   │ │
│ │                            │ │
│ │ ┌─ 底部输入/操作区 ─────┐  │ │
│ │ │  [开始创作] 或 输入框  │  │ │
│ │ └───────────────────────┘  │ │
│ └────────────────────────────┘ │
└────────────────────────────────┘
```

**流程模式分级入口：**
- 高频常驻：「工作流」「聊天」保留为顶部 Segmented Control，一次点击切换
- 低频收纳：「群聊·高级」「反推」「矩阵编排」收进"创作方式"菜单（··· 按钮展开 Popover），Popover 内显示完整列表 + 描述
- 运行中锁定：创作流程运行时，只展示当前模式名称 + 阶段进度 + 取消操作，禁止切换

### 3.3 矩阵视图渐进式展示

**当前问题：** 所有实体 × 所有章节的网格同时可见，信息量巨大。

**在既有虚拟化能力上调整默认状态和视觉层级**（修订：不是重新建设虚拟滚动）：

1. **概览层**（默认）：只显示实体行（名称 + 类型图标 + 出场跨度色条），不展开子轨道。行高 36px，一屏可见 20+ 实体。
2. **聚焦层**（点击实体行）：展开该实体的子轨道（维度变化时间线），其他行保持概览。使用 `layout` 动画平滑展开。
3. **详情层**（双击/右键）：弹出浮层显示实体完整信息 + 编辑表单。

**章节列头改为时间轴：** 当前章节列头是静态数字，改为可缩放的时间轴（已有 Ctrl+滚轮缩放基础），播放头章节高亮为竖线而非背景色块。

## 四、视觉设计升级

### 4.1 Type Scale 建立

当前只有 14px 基准 + 零散的 `text-[11px]`、`text-[10px]`。建立明确的分层字阶：

| 层级 | 大小 | 行高 | 用途 |
|------|------|------|------|
| Display | 20px / 1.2 | 24px | 页面标题（项目名） |
| Heading | 15px / 1.33 | 20px | 面板标题、章节名 |
| Body | 14px / 1.6 | 22px | 正文编辑器、消息文本（保留 14px，行高提高到 1.6） |
| Caption | 12px / 1.33 | 16px | 辅助信息、时间戳、状态标签 |
| Micro | 11px / 1.27 | 14px | 矩阵单元格、极紧凑标签 |

**修订说明：** 正文编辑器和消息正文保留 14px。中文长文本写作在 Windows 非 Retina 环境下 13px 偏小，会伤害阅读体验。信息密度的提升通过面板折叠和布局优化实现，而非全局缩小字号。

**密度偏好：** 增加"紧凑 / 标准"密度设置（持久化），紧凑模式下面板标题和辅助信息可降 1px，但正文编辑器始终不低于 14px。

### 4.2 边框与阴影分层规则

**修订：阴影不能替代全部边界。** 深色主题下纯阴影几乎不可见，浅色主题下面板边界会模糊。采用分层规则：

```css
/* Level 0: 同一工作区内的普通分区——保留低对比 1px border */
--border-subtle: 1px solid var(--color-border);  /* 现有 token */

/* Level 1: 独立、可拖动、可浮起的面板——轻边框 + 阴影 */
--shadow-raised: 0 1px 2px rgba(0, 0, 0, 0.04), 0 2px 8px rgba(0, 0, 0, 0.04);

/* Level 2: Popover、Dialog、HoverCard——更强阴影 + 描边 */
--shadow-overlay: 0 4px 12px rgba(0, 0, 0, 0.08), 0 12px 32px rgba(0, 0, 0, 0.06);
```

**应用规则：**
- 同一工作区内的普通分区（编辑器与矩阵之间、Tab 栏与内容之间）：保留低对比 1px border
- 独立可拖动面板（侧栏、右侧停靠面板）：轻边框 + Level 1 阴影
- Popover、Dialog、HoverCard、下拉菜单：Level 2 阴影 + 描边
- 卡片/输入框：保持现有 inset border，不改动

### 4.3 同心圆角规则

当前 `rounded-lg`（8px）到处使用，嵌套时内外圆角相同。改为：

```
外层容器: rounded-xl (10px)
  └─ 内层元素: rounded-lg (8px)  // 10 - 2(padding) ≈ 8
      └─ 更内层: rounded-md (6px)
```

具体场景：
- 面板容器：`rounded-xl`（10px）
- 面板内的卡片/输入区：`rounded-lg`（8px）
- 卡片内的按钮/标签：`rounded-md`（6px）
- 小徽章/胶囊：`rounded-full`

### 4.4 色彩微调

主色 `#4b3fe3` 饱和度偏高，长时间使用容易视觉疲劳。建议：

- 主色调整为 `#5B4FE8`（稍微提亮，降低对比刺激）
- 增加主色的 tint 梯度：`primary/5`、`primary/10`、`primary/20` 用于背景着色
- 成功色从 `#15a877` 调整为 `#10B981`（Tailwind emerald-500，更现代）
- 增加 `warning` 语义色：`#F59E0B`（当前缺失）

### 4.5 间距系统统一

当前 `px-2`、`px-2.5`、`px-3` 混用。统一为 4px 基准的间距 scale：

| Token | 值 | 用途 |
|-------|-----|------|
| space-1 | 4px | 图标与文字间距、紧凑标签内边距 |
| space-2 | 8px | 列表项间距、按钮内边距 |
| space-3 | 12px | 卡片内边距、段落间距 |
| space-4 | 16px | 面板内边距、区块间距 |
| space-6 | 24px | 大区块分隔 |

## 五、交互优化

### 5.1 动效语言统一

**修订：动效以"状态变化"为中心，不全量加 stagger。** 明确适用边界：

| 场景 | 动效规则 |
|------|----------|
| 面板开关、详情抽屉 | 160-220ms 的 transform + opacity，使用 `cubic-bezier(0.2, 0, 0, 1)` |
| Tab/Segmented 切换 | 共享指示器或 layout 动画（framer-motion `layoutId`） |
| AI 流式消息 | 不使用列表 stagger，只显示低干扰的流式光标和渐显 |
| 虚拟矩阵滚动 | 禁止进入动画，保证滚动稳定 |
| 批量列表初次进入 | 最多前 6-8 项使用 stagger（60ms 间隔），超出直接显示 |
| 减弱动效偏好 | 保留现有 `prefers-reduced-motion`，新增动画必须遵守 |

**进入动画：** 分层 stagger，每层延迟 60ms，最多 8 项

```tsx
const containerVariants = {
  hidden: { opacity: 0 },
  visible: {
    opacity: 1,
    transition: { staggerChildren: 0.06, delayChildren: 0 }
  }
}

const itemVariants = {
  hidden: { opacity: 0, y: 8 },
  visible: {
    opacity: 1, y: 0,
    transition: { type: "spring", duration: 0.3, bounce: 0 }
  }
}
```

**退出动画：** 比进入更轻——只做 opacity + 微小位移（4px），时长 150ms。

**按压反馈：**
- Primary / Secondary Button、Icon Button、卡片式决策按钮使用 `active:scale-[0.97] transition-transform duration-100`
- Tab、列表行、矩阵单元格、拖拽元素和分割条不使用缩放；仅通过背景、边框、颜色或阴影变化提供反馈
- 虚拟列表和矩阵内避免 transform，防止绘制抖动

### 5.2 快捷键体系

当前缺少系统性的快捷键（矩阵已有 react-hotkeys-hook 基础）。建议：

| 快捷键 | 功能 |
|--------|------|
| `Cmd/Ctrl+B` | 切换左侧栏 |
| `Cmd/Ctrl+J` | 切换右侧面板 |
| `Cmd/Ctrl+1/2/3` | 切换主工作区模式（写作/矩阵/分屏） |
| `Cmd/Ctrl+Shift+Enter` | 启动创作流程（仅非输入区） |
| `Cmd/Ctrl+Enter` | 提交当前对话输入（仅对话输入框） |
| `Cmd/Ctrl+Shift+F` | 切换专注模式（修订：不用双击，避免与文字选择冲突） |
| `Cmd/Ctrl+.` | 聚焦到输入框 |
| `Esc` | 关闭浮层/退出专注模式 |
| `Cmd/Ctrl+←/→` | 切换章节 |

**焦点冲突处理：** `Cmd/Ctrl+Shift+Enter` 在输入框聚焦时不触发；`Cmd/Ctrl+Enter` 仅在对话输入框中提交消息；`Esc` 保留编辑器和输入控件的默认行为，优先关闭建议面板、浮层或退出专注模式。输入区域包括 Tiptap 编辑器、文本框、搜索框和对话输入框。所有快捷键在设置页可发现、可自定义。

### 5.3 矩阵交互增强

在既有能力上优化（修订：以下能力大部分已存在，重点是调整默认行为和视觉层级）：

- **悬停预览：** 将 HoverCard 触发延迟从当前值调整为 300ms，减少误触
- **拖拽编排：** 已有基础，优化拖拽时的视觉反馈（目标列高亮 + 放置预览）
- **批量选择：** `Shift+Click` 选择多个实体行，底部浮出批量操作栏
- **搜索过滤：** 已有基础，增加 `Cmd/Ctrl+F` 快捷键触发，匹配实体名高亮，不匹配行淡化
- **渐进展示：** 子轨道默认收起（当前默认展开），点击行展开

### 5.4 对话面板交互

- **消息流自动滚动优化：** 只在用户位于底部时自动滚动；用户向上翻阅时显示"↓ 新消息"浮动按钮
- **Checkpoint 决策卡片化：** 当前的 checkpoint 选项改为明确的卡片式按钮组（approve/revise/reject），每个选项带简短说明
- **流式输出光标：** AI 生成时显示闪烁光标 + 渐入文字，而非整段突然出现
- **消息分组：** 同一 Agent 的连续消息合并为一个气泡组，减少视觉噪音

### 5.5 编辑器体验

- **专注模式：** 通过 `Cmd/Ctrl+Shift+F` 或编辑器右上角显式按钮进入全屏写作（隐藏所有面板），`Esc` 退出。不绑定双击（避免与文字选择冲突）。
- **字数统计浮动化：** 从固定位置改为编辑器右下角的半透明浮动徽章
- **章节切换过渡：** 切换章节时编辑器内容做 crossfade（200ms），而非硬切

## 六、组件级改造清单

### 6.1 高优先级（体验提升最大）

| 组件 | 当前问题 | 改造方向 |
|------|----------|----------|
| `novel-workspace.tsx` | 五面板并列，无法聚焦 | 模式切换 + 面板折叠 + 状态模型 |
| `novel-conversation-panel.tsx` | 5 Tab 挤压，状态栏占空间 | 高频常驻 + 低频收纳，状态栏合并到消息流 |
| `matrix-row.tsx` | 行内信息过密，子轨道默认展开 | 概览/聚焦两态，子轨道默认收起 |
| `resizable-splitter.tsx` | 3px 太细，拖拽手感差 | 改为 6px 可见区域 + 12px 热区，拖拽时显示尺寸提示 |

### 6.2 中优先级（视觉一致性）

| 组件 | 改造方向 |
|------|----------|
| 面板容器 | 分层边框/阴影规则，同心圆角 |
| Tab 组件 | 统一为胶囊式 segmented control，带 layout 动画滑块 |
| 按钮体系 | 统一 active:scale，增加 ghost/soft 变体 |
| 表单控件 | 统一 focus ring 样式（primary/20 光晕），增加过渡 |
| 消息气泡 | AI/用户气泡视觉区分更明确，流式光标 |

### 6.3 低优先级（锦上添花）

| 组件 | 改造方向 |
|------|----------|

## 七、技术实施建议

### 7.1 矩阵性能：基于实测优化

**修订：项目已实现横纵虚拟化，不重新引入。**

实施策略：
- 在「100 个实体、80 章、展开 10 个子轨道」场景下测量帧率、内存与交互延迟
- 仅针对实测瓶颈优化 overscan、缓存、行高计算和渲染稳定性
- 验证子轨道默认收起后的首屏渲染时间改善

### 7.2 面板状态持久化

**需要持久化的（收口到 novel-ui-store）：**
- 左栏显示状态（展开/折叠）
- 右栏显示状态（关闭/侧滑/停靠）
- 右栏停靠偏好
- 主区模式（写作/矩阵/分屏）
- 分屏比例
- 面板宽度（sidebarWidth、detailWidth）
- 信息密度偏好（紧凑/标准）

**不应持久化的：**
- 当前临时选中项
- 创作流程运行态
- 消息滚动位置
- 短暂的 Hover/Popover 状态

**迁移策略：** 旧版 localStorage 数据需要兼容迁移。设置版本号，读取时检测旧格式并转换。默认值与最小值需明确（如 sidebarWidth 默认 220、最小 180、最大 360）。

### 7.3 动效性能

- 面板展开/折叠：使用 `transform: translateX` 而非 `width` 动画（GPU 合成）
- 列表 stagger：限制同时动画元素数量（最多 8 个，超出直接显示）
- 矩阵行展开：使用 `grid-template-rows: 0fr → 1fr` 过渡（无需 JS 计算高度）
- 虚拟列表内禁止进入动画

### 7.4 组件拆分建议

`novel-workspace.tsx` 当前承载过多职责（布局 + 状态管理 + 流程控制）。建议拆分为：

```
novel-workspace.tsx          → 纯布局壳（面板排列 + 折叠逻辑）
novel-workspace-header.tsx   → 顶部标题栏 + 视图切换
novel-workspace-body.tsx     → 主内容区（模式切换逻辑）
use-novel-workspace-state.ts → 面板状态 hook（宽度/折叠/模式，收口到 zustand）
```

### 7.5 无障碍与系统高对比

本次不新增应用内“高对比主题”。通过 `@media (forced-colors: active)` 支持 Windows 等系统的高对比模式：

- 不覆盖系统强制色，依赖语义化 HTML、原生焦点样式和 `currentColor`
- 为按钮、Tab、输入框、分割条和 Popover 保留可见边界与焦点轮廓
- 禁止仅依赖颜色传达选中、错误、运行中等状态，需同时提供图标、文字或形状提示
- 在 Windows 系统高对比模式下手动验证工作台的可读性、键盘导航和关键操作

## 十、迁移策略

当前工作区已存在大量未提交的矩阵和对话相关改动。改版不能与它们混在同一个大提交里。

**执行顺序：**
1. 先稳定当前变更（提交或 stash），确保 main 分支可运行
2. 按 Phase 拆分独立 PR，每个 Phase 可独立合入和回滚
3. Phase 1（状态模型）是后续所有改动的基础设施，必须最先合入
4. 设计 token 扩展（main.css 变量新增）不删除旧变量，新旧并存过渡
5. 组件样式替换分批进行：先高频组件（按钮、输入框、Tab），再低频组件

**风险控制：**
- 每个 Phase 合入前在浅色/深色/减少动效三种模式下手动验证
- 面板状态迁移需要处理旧格式兼容（检测版本号，自动转换）
- 矩阵性能优化不能破坏现有虚拟化和拖拽能力

## 十二、设计参考

整体方向参考 Linear（信息密度 + 快捷键驱动）和 Notion（渐进式展示 + 干净排版）的交集：

- 像 Linear 一样：高密度但不拥挤，键盘优先，面板可快速收起
- 像 Notion 一样：内容层级清晰，留白充足，编辑体验沉浸
- 避免：VS Code 式的"所有面板同时可见"、Figma 式的"工具栏密集排列"
