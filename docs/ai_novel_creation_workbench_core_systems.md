# 1. 文档定位

这份文档讨论的不是某一种固定技术实现，也不是某一套 JSON、数据库或代码结构，而是一个 AI 小说创作工具应当具备的核心系统概念。

如果目标只是做一个“AI 续写器”，那么让模型根据上下文继续生成文本就够了。

但如果目标是做一个真正可长期创作的 **AI 小说创作工作台**，系统的核心就不能只是“生成正文”，而应该是长期维护一个不断变化的故事系统。

小说创作的难点不在于单次生成一段文字，而在于：

- 长期设定不崩
- 人物行为不跳
- 伏笔不丢
- 线索不断
- 情节有推进
- 冲突有升级
- 信息揭露有节奏
- 读者持续有期待
- AI 能记住并正确使用已有故事状态

因此，AI 小说创作工具的核心应当围绕以下能力构建：

```text
状态管理
任务推进
约束控制
信息分配
人物变化
伏笔回收
冲突升级
生成验收
```

# 2. 总体设计思想

AI 小说系统不应该被设计成：

```text
用户输入要求
↓
AI 生成正文
↓
保存正文
```

而应该被设计成：

```text
读取故事状态
↓
判断当前阶段
↓
确定本章叙事任务
↓
加载创作约束
↓
分配信息差
↓
控制角色弧光
↓
生成正文
↓
检查章节质量
↓
更新故事状态
↓
进入下一轮创作
```

也就是说，正文只是结果，真正的核心是背后这一套故事运行机制。

可以把小说系统理解成一个“故事运行时”：

```text
故事不是静态资料库，而是一个持续变化的状态系统。
AI 不是单纯写手，而是被导演系统、约束系统、记忆系统共同调度的创作执行者。
```

# 3. 核心系统总览

一个成熟的 AI 小说创作工作台，建议至少关注以下核心系统。

## 第一优先级核心系统

这几类是最基础、最重要的系统：

1. 故事状态系统
2. 创作约束系统
3. 叙事任务系统
4. 角色弧光系统
5. 信息差系统
6. 伏笔与线索系统
7. 冲突升级系统
8. 章节验收系统

## 第二优先级增强系统

这些系统会显著提高长篇质量、风格稳定性和读者体验：

9. 节奏控制系统
10. 世界规则系统
11. 风格与文体系统
12. 长期记忆分层系统
13. 作者意图系统
14. 多 Agent 协作系统
15. 读者体验系统

这些系统之间不是彼此孤立的，而是共同服务于一个目标：

```text
让 AI 从“随便续写”变成“基于故事状态进行受控创作”。
```

# 4. 故事状态系统

## 4.1 系统定位

故事状态系统是所有系统的地基。

创作约束系统依赖故事状态，叙事任务系统依赖故事状态，角色弧光、伏笔、线索、冲突、信息差也都依赖故事状态。

它要回答：

```text
故事现在走到哪里了？
哪些事情已经发生？
哪些信息已经公开？
哪些角色发生了变化？
哪些冲突正在进行？
哪些伏笔还没回收？
当前章节属于哪个剧情阶段？
```

如果没有故事状态系统，AI 只能依靠模糊上下文写作，无法稳定判断当前剧情位置。

## 4.2 故事状态不是角色资料

很多小说工具只存资料：

```text
角色 A：冷静、聪明、北境军少主。
角色 B：神秘、危险、持有玄铁令。
地点 C：皇城。
道具 D：玄铁令。
```

这些只是静态设定。

真正重要的是动态状态：

```text
角色 A 现在是否信任角色 B？
角色 A 是否知道角色 B 的秘密？
玄铁令现在在谁手里？
玄铁令的真实用途有没有被揭露？
皇城旧案现在调查到哪一步？
某个伏笔是未触发、已强化、可回收，还是已回收？
某个冲突是潜伏、爆发、升级，还是解决？
```

因此，故事状态系统管理的是小说当前运行时状态，而不是单纯的人物卡、世界观卡或道具卡。

## 4.3 故事状态需要管理的内容

故事状态至少应该覆盖：

```text
角色当前状态
关系当前状态
势力当前状态
物品当前归属
地点当前状态
线索当前进度
伏笔当前阶段
冲突当前强度
读者当前已知信息
角色当前已知信息
剧情当前阶段
当前卷目标
当前章节目标
```

例如，写第 30 章时，AI 不应该只知道“林寒是主角”，而应该知道：

```text
林寒现在是否受伤？
林寒是否已经知道沈烬的秘密？
林寒和沈烬现在是敌对、合作，还是试探性信任？
玄铁令现在在谁手里？
皇城旧案调查到哪一步？
北境军是否已经公开反叛？
```

## 4.4 一句话总结

> 创作约束系统负责判断“能不能写”，故事状态系统负责告诉它“现在是什么情况”。

# 5. 创作约束系统

## 5.1 系统定位

创作约束系统不是资料库，而是一套让 AI 写作时知道边界、知道阶段、知道任务、知道后果的创作控制思想。

它的目标不是限制 AI 创造力，而是让 AI 的发挥始终服务于小说整体。

它要解决的问题包括：

```text
角色突然变蠢、变强、变性格
世界观规则前后矛盾
伏笔埋了不收
线索断裂
角色知道了自己不该知道的秘密
章节只是在水字数，没有推进主线
AI 每次生成都像失忆
```

## 5.2 创作约束的本质

创作约束不是简单设定。

例如：

```text
林寒是北境军少主。
沈烬持有玄铁令。
玄铁令和皇城旧案有关。
```

这些只是资料。

真正的约束是：

```text
第 12 章以前，林寒不能知道玄铁令的真实用途。
沈烬不能主动暴露自己和皇城旧案的关系。
玄铁令必须在第 3 卷前至少出现 3 次。
林寒和沈烬的关系在第 8 章后从“合作”转为“互相试探”。
北境军不能在第 2 卷前公开反叛。
如果角色使用血契术，必须付出寿命代价。
```

也就是说，约束系统关注的是：

```text
当前阶段允许发生什么？
当前阶段禁止发生什么？
当前阶段必须推进什么？
当前阶段需要隐藏什么？
当前阶段有哪些未完成的叙事债务？
```

## 5.3 五类核心约束

### 5.3.1 事实约束

已经确定的事情不能随便推翻。

例如：

```text
林寒是北境军少主。
沈烬持有玄铁令。
血契术必须消耗寿命。
皇城禁军不能进入北境圣地。
```

事实约束需要区分：

```text
固定事实：不能改。
阶段事实：当前阶段成立，以后可以变。
待定事实：还没完全确认，可以模糊处理。
```

### 5.3.2 认知约束

角色不能知道自己不该知道的事。

例如作者知道：

```text
沈烬是皇城旧案参与者。
玄铁令是打开皇陵机关的钥匙。
女主真实身份是前朝公主。
```

但林寒当前只知道：

```text
沈烬行踪可疑。
玄铁令很重要。
女主身份有问题。
```

那么林寒可以怀疑，但不能直接说出真相。

认知约束控制的是：

```text
谁知道什么？
谁不知道什么？
谁怀疑什么？
谁误解什么？
谁掌握真相但在隐瞒？
```

### 5.3.3 阶段约束

不同剧情阶段允许做不同的事。

例如“玄铁令真实用途”：

```text
前期：只能出现，不能解释。
中期：可以制造怀疑，不能完全揭露。
后期：可以揭露一部分。
高潮：正式回收。
```

阶段约束控制的是节奏：

```text
现在该埋。
现在该压。
现在该暗示。
现在该升级。
现在该揭露。
现在该回收。
```

### 5.3.4 叙事债务约束

小说里任何被抛出来但还没完成的东西，都是叙事债务。

例如：

```text
一个未解释的物品
一句奇怪的台词
一个未揭露的身份
一段异常关系
一个没有兑现的承诺
一次未完成的复仇
一个未回收的伏笔
一条调查线索
一个正在升级的矛盾
```

叙事债务系统要持续追踪：

```text
这个债务什么时候产生？
它现在是什么状态？
它和哪些人物、事件、道具有关？
它应该什么时候强化？
它最晚什么时候回收？
它是否已经过期？
它是否被 AI 忘了？
```

### 5.3.5 人物弧线约束

角色变化必须有过程。

例如林寒对沈烬的信任变化不能是：

```text
敌意 → 生死相托
```

中间至少应该有：

```text
敌意 → 警惕 → 被迫合作 → 短暂默契 → 试探性信任 → 真正信任
```

人物弧线约束控制的是：

```text
人物现在处于什么心理阶段？
关系现在处于什么阶段？
下一步最多能推进到哪里？
不能越级跳到什么程度？
```

## 5.4 创作约束系统的核心判断

在每次创作前，系统都应该问：

```text
当前章节处于什么阶段？
本章必须完成什么叙事任务？
本章禁止发生什么？
哪些信息可以揭露，哪些信息必须隐藏？
哪些伏笔处于什么状态？
人物关系现在处于哪一步？
世界规则有没有被触碰？
写完后故事状态发生了什么变化？
```

## 5.5 一句话总结

> 创作约束系统 = 把小说从“自由生成文本”变成“在当前剧情状态下受控推进”。

# 6. 叙事任务系统

## 6.1 系统定位

叙事任务系统是防止 AI 写水文的关键系统。

很多 AI 小说工具不是写不出文字，而是写出来的章节“好像有内容，但没有推进”。

叙事任务系统要保证每一章都有功能。

## 6.2 每章都应该承担任务

每一章至少应该承担一种叙事任务：

```text
推进主线
推进支线
制造冲突
升级冲突
释放信息
隐藏信息
强化伏笔
回收伏笔
改变人物关系
改变人物认知
制造反转
制造悬念
完成阶段收束
引出新问题
```

例如第 12 章不能只是：

```text
林寒和沈烬在驿馆聊天。
```

它应该是：

```text
林寒和沈烬在驿馆试探对方。
通过对话推进密信暗纹线索。
同时强化林寒对沈烬的怀疑。
结尾让玄铁令再次出现，但不解释用途。
```

这才是有叙事任务的章节。

## 6.3 叙事任务系统的核心问题

创作前应当问：

```text
这一章的核心作用是什么？
它推进哪条线？
它改变了什么？
它留下了什么？
它不能解决什么？
它结束后，故事状态应该发生什么变化？
```

## 6.4 一句话总结

> 没有叙事任务系统，AI 会写出“漂亮但无效”的章节。

# 7. 角色弧光系统

## 7.1 系统定位

角色弧光系统是保证人物不崩的核心。

角色不是一张设定卡，而是一条变化曲线。

## 7.2 角色不是标签，而是阶段

例如：

```text
林寒：冷静、隐忍、重情义。
```

这只是标签。

真正有用的是：

```text
林寒当前处于“信任崩塌后的自我封闭阶段”。
他表面冷静，但对沈烬极度戒备。
他可以短暂合作，但不能主动交心。
他在第 18 章前不能重新建立信任。
```

## 7.3 角色弧光系统需要管理的内容

```text
角色的欲望
角色的恐惧
角色的误解
角色的底线
角色的秘密
角色的成长阶段
角色的关系变化
角色的心理状态
角色当前目标
角色当前压力
```

## 7.4 角色变化不能跳档

人物关系不能这样跳：

```text
敌对 → 生死相托
```

更合理的是：

```text
敌对 → 被迫合作 → 互相试探 → 短暂默契 → 信任萌芽 → 生死相托
```

角色弧光系统要控制：

```text
人物是否变化过快？
人物行为是否有动机？
人物选择是否符合当前压力？
人物是否跨过了不该跨过的心理阶段？
人物关系是否跳档？
```

## 7.5 一句话总结

> 角色弧光系统负责让人物“变化”，但不能“乱变”。

# 8. 信息差系统

## 8.1 系统定位

信息差系统是悬疑、权谋、反转、感情误会的核心。

小说的张力很大程度来自信息差。

## 8.2 信息需要分层

你需要区分：

```text
作者知道什么
读者知道什么
主角知道什么
反派知道什么
配角知道什么
某个势力知道什么
某个角色误以为什么
某个角色隐瞒了什么
```

例如：

```text
作者知道：沈烬参与皇城旧案。
读者知道：沈烬很可疑，但不知道真相。
林寒知道：沈烬和玄铁令有关。
沈烬知道：玄铁令真实用途。
苏晚知道：沈烬曾去过皇城地牢。
```

如果这些信息层级混乱，悬念会直接崩。

## 8.3 信息差系统关注的问题

```text
什么信息可以给读者？
什么信息只能给角色？
什么信息只能给反派？
什么信息当前必须隐藏？
什么信息可以误导？
什么信息什么时候揭露最有张力？
```

认知约束关注的是：

```text
角色不能知道不该知道的事。
```

信息差系统关注的是：

```text
读者、角色、作者之间的信息分配如何制造张力。
```

## 8.4 一句话总结

> 信息差系统决定悬念是否成立，反转是否有效。

# 9. 伏笔与回收系统

## 9.1 系统定位

伏笔与回收系统用于管理小说中“未来必须兑现的期待”。

伏笔不是简单地记录“这里埋了一个坑”，而是管理一个叙事元素从出现到强化再到回收的完整生命周期。

## 9.2 伏笔生命周期

一个伏笔通常经历：

```text
计划中
已埋下
已重复强化
已局部揭露
进入回收区
已回收
已废弃
```

不同状态下写法不同：

```text
已埋下：可以轻轻重复。
已强化：可以制造异常。
部分揭露：可以给出局部解释。
可回收：可以正式揭示。
已回收：不能继续当谜团写。
```

## 9.3 伏笔系统需要回答的问题

```text
伏笔第一次出现在哪里？
它和哪些角色、道具、事件相关？
它需要被重复几次？
它最早什么时候可以揭露？
它最晚什么时候必须回收？
它回收时要产生什么效果？
它是否已经被 AI 忘了？
它是否被过早解释了？
```

## 9.4 示例

以“玄铁令真实用途”为例：

```text
第 3 章：玄铁令出现。
第 6 章：敌人看到玄铁令后脸色变化。
第 10 章：玄铁令纹路与皇城旧案有关。
第 15 章：林寒发现它来自皇陵。
第 22 章：揭露它是皇陵机关钥匙。
```

这条伏笔线不能随机处理，而应该按照阶段逐渐强化。

## 9.5 一句话总结

> 伏笔系统管理的是“读者期待的种子如何长成剧情爆点”。

# 10. 线索推进系统

## 10.1 系统定位

伏笔偏向“未来回收”，线索偏向“当前推进”。

悬疑、权谋、探案、玄幻秘境、复仇线，都需要线索推进系统。

## 10.2 线索系统需要回答的问题

```text
当前线索链有哪些？
每条线索指向什么？
主角目前掌握到哪一步？
下一步应该发现什么？
哪些线索是误导？
哪些线索是真相碎片？
哪些线索需要组合才能得出结论？
```

## 10.3 示例

“皇城旧案”可以拆成多条线索：

```text
密信暗纹
玄铁令
地牢旧账
苏晚的身世
沈烬的旧伤
北境军叛徒名单
```

这些线索不能随机出现，而应该逐步拼接。

## 10.4 线索系统防止的问题

```text
线索突然断掉
线索跳过推理过程
主角凭空知道答案
线索太密导致节奏混乱
线索太少导致剧情停滞
```

## 10.5 一句话总结

> 线索系统负责让剧情“有路可走”，不是靠 AI 硬拐。

---

# 11. 冲突升级系统

## 11.1 系统定位

小说的推进本质上靠冲突。

冲突升级系统负责管理冲突的类型、强度、阶段和升级节奏。

## 11.2 冲突类型

冲突可以分为：

```text
人物内心冲突
人物关系冲突
阵营冲突
利益冲突
道德冲突
身份冲突
情感冲突
世界规则冲突
生存冲突
```

## 11.3 冲突生命周期

每个冲突都有生命周期：

```text
潜伏
出现
升级
爆发
反转
暂时解决
彻底解决
转化为新冲突
```

例如“林寒与沈烬的信任危机”可以这样升级：

```text
怀疑
↓
试探
↓
隐瞒
↓
误会
↓
合作失败
↓
信任破裂
↓
真相揭露
↓
关系重构
```

## 11.4 冲突系统防止的问题

AI 经常犯两个问题：

```text
冲突刚出现就解决。
冲突升级没有原因。
```

冲突升级系统应该提醒：

```text
当前冲突不能解决，只能升级。
当前冲突应该从“怀疑”进入“试探”。
本章需要制造一次小型误会。
不要让双方坦白。
```

## 11.5 一句话总结

> 冲突升级系统负责让小说持续有张力。

---

# 12. 节奏控制系统

## 12.1 系统定位

节奏控制系统是长篇小说尤其重要的系统。

小说不能一直高潮，也不能一直铺垫。

## 12.2 章节节奏类型

节奏系统要管理：

```text
铺垫章
推进章
冲突章
转折章
高潮章
缓冲章
揭秘章
收束章
```

如果连续很多章都是高强度战斗，读者会疲劳。

如果连续很多章都是聊天铺垫，读者会流失。

## 12.3 节奏系统需要判断的问题

```text
最近几章是否太平？
最近几章是否太密？
是否需要一个小高潮？
是否需要缓冲？
是否该推进主线？
是否该回收一个伏笔？
是否该制造新危机？
```

## 12.4 简单节奏模型

一个简单的节奏模式可以是：

```text
铺垫
推进
小冲突
线索发现
关系变化
小高潮
余波
新问题
```

## 12.5 一句话总结

> 节奏系统负责让读者“持续想看”，而不是被信息或空转拖垮。

---

# 13. 世界规则系统

## 13.1 系统定位

世界规则系统对玄幻、科幻、奇幻、修仙、赛博朋克等类型尤其重要。

它负责维护小说世界的可信度。

## 13.2 世界规则包括什么

```text
力量体系
魔法规则
科技边界
政治制度
宗门制度
法律规则
经济规则
地理限制
交通限制
信息传播限制
种族规则
禁忌规则
代价规则
```

## 13.3 规则最重要的是代价

例如：

```text
血契术可以强行控制他人，但会消耗施术者寿命。
传送阵只能连接有灵脉的地点。
皇族血脉才能打开皇陵外门。
高阶修士不能随意进入凡人城池，否则会触发天律。
```

AI 为了剧情方便，经常会破坏规则：

```text
为了赶路，随便开传送阵。
为了打赢，突然无代价爆发禁术。
为了制造爽点，让低阶角色轻松击败高阶角色。
```

## 13.4 世界规则系统需要检查的问题

```text
能力使用是否符合规则？
是否支付了代价？
等级差是否合理？
政治行为是否符合制度？
地理移动是否符合距离和交通限制？
信息传播是否符合时代与世界观？
```

## 13.5 一句话总结

> 世界规则系统负责维护小说世界的可信度。

---

# 14. 读者体验系统

## 14.1 系统定位

读者体验系统是很多工具会忽略的系统。

小说不是只要逻辑没错就好，还要让读者有体验。

## 14.2 读者体验关注什么

```text
悬念感
期待感
爽点
压迫感
情绪释放
反转冲击
人物共情
节奏舒适度
信息密度
章节钩子
```

## 14.3 读者体验系统需要问的问题

```text
读者有没有新的问题？
读者有没有期待下一章？
这一章有没有情绪波动？
这一章有没有爽点或压迫点？
结尾有没有钩子？
信息是否太多？
对话是否太长？
```

一章在逻辑上完全正确，但如果它：

```text
没有冲突
没有变化
没有悬念
没有情绪
没有钩子
```

那它依然不好看。

## 14.4 一句话总结

> 读者体验系统负责让小说不只是“对”，而是“好看”。

---

# 15. 章节验收系统

## 15.1 系统定位

章节验收系统是工程化创作中非常实用的系统。

每章生成后，不要只看“有没有写完”，而要验收。

## 15.2 验收维度

可以从以下维度验收：

```text
设定一致性
角色一致性
叙事任务完成度
线索推进度
伏笔状态变化
冲突变化
节奏合理性
信息揭露是否越界
读者钩子是否存在
语言风格是否符合
```

## 15.3 章节验收系统要判断的问题

```text
这一章是否值得进入正文？
是否需要重写？
是否只需要局部修订？
是否缺少叙事价值？
是否破坏后续安排？
```

它不只是找错，还要判断章节是否具有叙事价值。

## 15.4 一句话总结

> 章节验收系统负责把 AI 生成内容从“草稿”筛成“可用章节”。

---

# 16. 风格与文体系统

## 16.1 系统定位

风格与文体系统用于保持小说语言、叙述方式、角色声音的长期一致性。

它不应该只写一句“文风细腻”，而要具体管理可执行的风格要素。

## 16.2 风格系统需要管理什么

```text
叙述视角
语言密度
句式节奏
对话风格
心理描写比例
动作描写比例
环境描写比例
信息释放方式
章节结尾方式
人物说话习惯
禁用表达
常用意象
```

## 16.3 示例

```text
林寒说话短、冷、克制。
沈烬说话含蓄，喜欢反问。
苏晚说话柔和，但关键时刻会直接。
旁白偏冷峻，不使用网络化表达。
战斗描写重视动作逻辑，不堆技能名。
```

AI 很容易在长篇中风格漂移。

风格系统的目标是让不同章节保持统一，同时不同角色有自己的声音。

## 16.4 一句话总结

> 风格系统负责让小说不是“每章像不同人写的”。

---

# 17. 长期记忆分层系统

## 17.1 系统定位

小说工具的记忆不能只有一种。

不同信息的重要性、作用范围、可见性、时效性都不一样。

## 17.2 记忆应当分层

至少可以分为：

```text
永久设定记忆
当前卷记忆
当前剧情线记忆
当前章节上下文
角色个人记忆
读者已知信息
作者规划信息
废弃设定记忆
```

## 17.3 为什么要分层

因为不是所有信息都应该同等重要。

例如：

```text
世界规则：永久重要。
某章天气：短期重要。
某个临时路人：可能只在一章重要。
废弃设定：不能再被当成有效设定。
作者剧透：不能直接给角色或读者。
```

如果记忆不分层，AI 会出现：

```text
把废弃设定拿回来用。
把作者规划当成已发生剧情。
把未来剧情提前写出来。
把临时细节当成永久设定。
```

## 17.4 一句话总结

> 长期记忆分层系统负责让 AI 记得正确的东西，并在正确的范围内使用。

---

# 18. 作者意图系统

## 18.1 系统定位

作者意图系统用于保存“为什么这么写”。

AI 不应该只理解文本内容，还要理解作者意图。

## 18.2 表层内容与作者意图

例如作者写：

```text
沈烬递给林寒玄铁令时，手指微微一顿。
```

表层内容是动作。

作者意图可能是：

```text
暗示沈烬知道玄铁令真正用途。
制造他和旧案的关联。
让读者怀疑但不确定。
```

如果系统只记录表层，就会丢失创作目的。

## 18.3 作者意图系统需要记录什么

```text
这个情节为什么存在？
这个伏笔未来要干什么？
这个角色当前为什么这样行动？
这个场景承担什么功能？
这段对话想制造什么效果？
```

## 18.4 一句话总结

> 作者意图系统负责保存“为什么这么写”，而不是只保存“写了什么”。

---

# 19. 多 Agent 协作系统

## 19.1 系统定位

如果你已经有自己的 Agent 工具，多 Agent 协作系统非常重要。

不要让一个 Agent 负责全部事情。

关键不是 Agent 数量，而是职责边界。

## 19.2 推荐的 Agent 职责划分

可以从概念上拆成：

```text
导演 Agent：判断章节任务和剧情阶段
设定 Agent：维护世界观和规则
角色 Agent：维护人物弧光和关系
线索 Agent：维护伏笔、线索、叙事债务
写作 Agent：负责正文生成
审稿 Agent：检查一致性和可读性
修订 Agent：根据问题重写局部
记忆 Agent：沉淀新状态
```

## 19.3 常见错误

最常见的错误是：

```text
写作 Agent 既规划、又写文、又检查、又更新记忆。
```

这样很容易互相污染。

更好的流程是：

```text
导演定任务
设定给边界
角色给状态
线索给债务
写作出正文
审稿找问题
修订改文本
记忆沉淀变化
```

## 19.4 一句话总结

> 多 Agent 系统的核心不是“多”，而是“职责隔离”。

---

# 20. 系统之间的协作关系

## 20.1 一次完整创作流程

一个比较理想的创作闭环如下：

```text
故事状态系统
↓
判断当前故事位置
↓
叙事任务系统
↓
确定本章功能
↓
创作约束系统
↓
明确允许、禁止、必须推进的内容
↓
信息差系统
↓
控制谁知道什么、读者看到什么
↓
角色弧光系统
↓
控制人物心理与关系推进幅度
↓
伏笔与线索系统
↓
决定本章要强化、推进或回收哪些内容
↓
冲突升级系统
↓
决定冲突是否升级、爆发或暂缓
↓
风格与文体系统
↓
统一叙述口吻和角色声音
↓
写作 Agent
↓
生成正文
↓
章节验收系统
↓
检查一致性、任务完成度和读者体验
↓
记忆系统
↓
更新故事状态、角色状态、线索状态、伏笔状态
```

## 20.2 最小闭环

如果不想一开始做复杂，至少要保证这个最小闭环：

```text
故事状态
↓
当前章节目标
↓
约束边界
↓
正文生成
↓
一致性审查
↓
状态更新
↓
下一章继续使用
```

可以概括为：

```text
记住过去
判断现在
控制生成
检查结果
沉淀变化
```

# 21. 推荐优先级

## 21.1 第一阶段：先解决“AI 写崩”问题

优先建设：

```text
故事状态系统
创作约束系统
章节验收系统
长期记忆分层系统
```

目标：

```text
不改固定设定
不提前泄露秘密
不忘记主要伏笔
不违反世界规则
写完后能更新状态
```

## 21.2 第二阶段：解决“AI 写水”问题

继续建设：

```text
叙事任务系统
线索推进系统
冲突升级系统
节奏控制系统
```

目标：

```text
每章都有明确作用
主线持续推进
冲突持续升级
章节不空转
```

## 21.3 第三阶段：解决“人物和体验”问题

继续建设：

```text
角色弧光系统
信息差系统
读者体验系统
风格与文体系统
```

目标：

```text
人物变化自然
悬念成立
反转有效
读者有期待
风格不漂移
```

## 21.4 第四阶段：解决“创作工作台”问题

最后完善：

```text
作者意图系统
多 Agent 协作系统
更细的世界规则系统
更复杂的伏笔与回收管理
```

目标：

```text
系统理解作者为什么这么写
各 Agent 职责清晰
长篇复杂结构可持续维护
```

---

# 22. 总结

AI 小说创作系统的核心不应该是“生成正文”，而应该是“维护故事系统”。

正文只是最终产物。

真正关键的是：

```text
故事状态是否准确？
章节任务是否明确？
创作边界是否清楚？
角色是否按照弧光发展？
信息差是否被正确管理？
伏笔是否有生命周期？
线索是否持续推进？
冲突是否逐步升级？
世界规则是否保持一致？
章节是否经过验收？
新状态是否被沉淀？
```

如果这些系统没有建立，AI 写作就会表现为：

```text
单章看起来不错，长篇越写越乱。
```

如果这些系统建立起来，AI 写作会变成：

```text
每一章都在当前故事状态下受控推进。
```

最终，你的工具就不再是一个“AI 辅助写作工具”，而是一个真正的：

```text
AI 小说创作工作台
```

它的核心能力是：

```text
长期维护一个不断变化的故事世界，并让每次生成都服务于这个世界的持续推进。
```
