# 新增小说功能接口清单

状态：与 2026-08-05 剧情推进模型重构方案、2026-08-07 P0/P1 增量 PRD、2026-08-10 P4 前置（Chunk 缓存与生成路径接入）对齐。本文是本轮新增功能的正式接口清单；接口响应统一使用 `{ code, data, message }`；时间为 UTC；ID 为 UUID。

## 1. 待审实体页面

页面：`apps/desktop/src/renderer/src/components/novel/entity-candidate-panel.tsx`

### 1.1 查询待审候选

`GET /projects/:projectId/entity-candidates?status=needs_review`

响应 `data`：

| 字段           | 类型                     | 说明         |
| -------------- | ------------------------ | ------------ |
| `candidates`   | `NovelEntityCandidate[]` | 候选列表     |
| `pendingCount` | `number`                 | 项目待审总数 |

候选字段：`id`、`projectId`、`chapterNumber`、`contentRevisionId`、`entityType`、`payload`、`status`、`reasonCode`、`createdAt`。

### 1.2 确认候选

`POST /entity-candidates/:id/confirm`

响应 `data`：`candidate`、`entityId`。候选确认、审核记录和正式 Conflict/Clue 晋升必须在同一事务内完成；失败时三者均不提交。

### 1.3 拒绝候选

`POST /entity-candidates/:id/reject`

请求：`{ reason: string }`，`reason` 必须为非空字符串。

响应 `data`：更新后的候选。审核记录包含 `decision`、`reason`、`actorId`、`createdAt` 及 `before/after/sourceRevision/chapterNumber` 审计上下文。

### 1.4 用户路径与复用

用户从小说工具栏的“待审实体”入口打开页面，页面先查询列表，再执行确认或拒绝。列表查询复用同一候选查询接口；确认和拒绝复用同一候选状态机与审核记录模型，不新增页面私有状态。

## 2. 正文版本链页面

页面：`apps/desktop/src/renderer/src/components/novel/chapter-version-panel.tsx`

### 2.1 查询正文版本

`GET /chapters/:chapterId/content-revisions`

响应 `data`：`ContentRevisionSummary[]`，字段为 `id`、`revision`、`phase`、`agentType`、`trigger`、`wordCount`、`status`、`createdAt`、`isCurrent`。

### 2.2 回滚正文

`POST /chapters/:chapterId/content-revisions/:revisionId/rollback`

响应 `data`：`appliedRevisionId`、`content`、`wordCount`。回滚必须创建新的 `rollback_applied` revision，并把原 current 标记为 `superseded`，不得把历史行直接改成 current。

### 2.3 用户路径与复用

用户从章节版本面板切换“版本链”页签，查询版本列表后点击某个历史版本回滚。列表和回滚均复用正文版本链；旧 `/versions` 接口只作为兼容读取，不与 V2 版本链混写。

## 3. 剧情推进轨道页面

页面：`apps/desktop/src/renderer/src/components/novel/narrative-track-panel.tsx`

### 3.1 查询剧情矩阵

`GET /projects/:projectId/narrative-matrix?asOfRevision=:sourceRevision`

`asOfRevision` 可选，用于校验客户端期望的源版本。当前投影是同步从 V2 账本构建，没有历史快照；版本不一致时必须返回 `stale=true`，不得静默伪装成历史版本。

响应 `data`：

| 字段             | 类型                         | 说明                          |
| ---------------- | ---------------------------- | ----------------------------- |
| `projectId`      | `string`                     | 项目 ID                       |
| `source`         | `'v2-ledger'`                | 数据来源                      |
| `sourceRevision` | `string`                     | 当前账本事实指纹              |
| `projectionLag`  | `number`                     | 投影延迟；同步构建为 `0`      |
| `stale`          | `boolean`                    | 源版本不匹配或存在 stale 事实 |
| `generatedAt`    | `number`                     | 生成时间                      |
| `rows`           | `NarrativeMatrixRow[]`       | Storyline 行                  |
| `sceneNodes`     | `NarrativeMatrixSceneNode[]` | 场景节点                      |
| `staleCount`     | `number`                     | 被排除的 stale progress 数    |

`rows[].progresses[]` 字段：`progressId`、`storylineId`、`sceneRevisionId`、`chapterNumber`、`type`、`primary`、`beforeState`、`afterState`、`summary`、`status`、`createdAt`。

### 3.2 用户路径与复用

用户从小说工具栏的“剧情轨道”入口打开页面，读取矩阵并按 `stale`/`staleCount` 显示待重建提示。矩阵接口只读；Storyline、Scene 的人工修改必须走 revision 接口，不允许直接 PATCH 投影字段。中间章重写导致的 stale 标记来自保存正文字段（见 §6），矩阵只负责呈现。

## 4. P3 上下文看板页面（T03-8，2026-08-10 新增）

页面：`apps/desktop/src/renderer/src/components/novel/p3-context-report-panel.tsx`（挂载于 `novel-workspace.tsx`，工具栏 Gauge 图标打开 Dialog）

### 4.1 查询 P3 上下文报告

`GET /projects/:projectId/p3/context-report?chapterNumber=&agentType=&budgetTokens=`

- `chapterNumber` 必填正整数；`agentType` 可选（director/writer/reviewer/memory，传时返回身份 token 与角色组装对照）；`budgetTokens` 可选（传时返回降级模拟）。

响应 `data`：

| 字段            | 类型                                                                 | 说明                                                        |
| --------------- | -------------------------------------------------------------------- | ----------------------------------------------------------- |
| `projectId`     | `string`                                                             | 项目 ID                                                     |
| `chapterNumber` | `number`                                                             | 章节号                                                      |
| `agentType`     | `string?`                                                            | 角色策略评估目标                                            |
| `baseline`      | `{ sharedChars, sharedTokens, chunkCount }`                          | flag 关闭时的现状基线（P3 验收对照，字符/token/chunk 数）    |
| `chunks`        | `P3ChunkEntry[]`                                                     | chunk 明细（`chunkId`/`title`/`priority`/`defaultMode`/`layer`/`charCount`/`tokens`） |
| `rolePolicies`  | `Array<{ agentType, policy: Array<{ chunkId, mode }> }>`             | 各 Agent 的 chunk 策略                                      |
| `degradation`   | 可选                                                                 | 降级模拟：`budgetTokens`/`tokensBefore`/`tokensAfter`/`savedTokens`/`savedPercent`/`appliedSteps`/`fits` |
| `identity`      | 可选                                                                 | 身份 token：`agentType`/`chars`/`tokens`                    |
| `roleAssembly`  | 可选                                                                 | P4 角色组装对照：`agentType`/`chars`/`tokens`/`savedTokens`/`savedPercent` |
| `catalog`       | `Array<{ chunkId, title, priority, defaultMode }>`                   | 目录完整清单（含未注入项）                                  |

### 4.2 上下文预览（后端/CLI，无独立页面）

`GET /projects/:projectId/context-preview?chapterNumber=&agentType=&mode=`

- `chapterNumber` 必填正整数；`mode` 为 `full`（默认，全量故事状态）或 `diff`（全局关键事实摘要 + 上一章变化 delta）。
- 返回 prompt-builder 实际注入的各 section 字符数、来源标记与前 200 字预览，用于审计 prompt 组装，不触发创作流。

### 4.3 用户路径与复用

用户从小说工具栏的看板入口（Gauge 图标）打开页面，选择章节/Agent/预算后查看 baseline 三指标、优先级汇总、角色组装对照、降级模拟与 chunk 明细。报告与预览共用 `prompt-builder` 的构建管线；chunk 目录/角色策略来自 `core/context-chunk.ts`（`CHUNK_CATALOG`/`ROLE_CONTEXT_POLICIES`），降级与 token 估算来自 `core/context-budget.ts`，均为纯函数，不落库、无独立写接口。

## 5. Agent 日志与 payload 外置（P1-2 冷热分离）

页面：`apps/desktop/src/renderer/src/components/novel/agent-log-panel.tsx`（既有页面；P1-2 改变详情读取语义，不改变列表）

### 5.1 列表（不加载 payload）

`GET /projects/:projectId/agent-logs?chapterNumber=&agentType=&limit=`

响应 `data`：`NovelAgentLogSummary[]`，只含元数据，不加载大文本。

### 5.2 详情（按需解压）

`GET /agent-logs/:id`

响应 `data`：`NovelAgentLog`，含 `systemPrompt`/`userMessage`/`result` 等全文。payload 外置开启时主表不存大文本，详情读取时从 `novel_agent_log_payloads` 解压返回（`content_hash` 可校验完整性）；主表读不到 payload 时回退旧字段（flag 关闭方式），保证 AgentLog 面板详情字段与迁移前一致。

### 5.3 清空与清理

- `DELETE /projects/:projectId/agent-logs` — 删除项目下全部日志。
- `POST /admin/agent-log-payloads/cleanup` — 按保留策略清理过期 payload：普通成功 30 天 / 失败 90 天 / 收藏或审计锁定长期；日志元数据不删。返回清理统计；定时调度由部署侧 cron/env 决定，本接口只提供手动触发。

### 5.4 用户路径与复用

用户从 Agent 日志面板查看调用列表，点击详情按需加载完整上下文。列表与详情复用 `novel_agent_logs` 元数据 + `novel_agent_log_payloads` 两条存储；无新增页面私有状态。

## 6. 中间章重写 → stale 标记 → 重建确认（剧情重构决策 4）

### 6.1 保存正文字的派生响应

`PATCH /chapters/:id`（body 含 `content` 时）

响应 `data` 除章节字段外附加 `derivedState`：

| 字段               | 类型       | 说明                                             |
| ------------------ | ---------- | ------------------------------------------------ |
| `isMiddleRewrite`  | `boolean`  | 是否为中间章重写（本章之后存在非空正文章节）     |
| `staleMarked`      | `number?`  | 被标记 stale 的推进记录数                        |
| `affectedChapters` | `number[]?`| 受影响的后续章节号                               |
| `message`          | `string?`  | 供前端提示的说明文案                             |

### 6.2 用户路径与语义

用户在正文编辑器保存中间章正文 → 若 `isMiddleRewrite=true`，前端 toast 提示影响范围并提供“从本章开始重建”入口。**保存正文不得隐式触发重建**；重建必须由用户查看影响范围并再次确认后启动。stale 的推进记录不进入矩阵当前态（`narrative-matrix` 的 `stale=true`/`staleCount` 呈现待重建）。

### 6.3 待决

设计契约中的 `POST /projects/:id/rebuild?fromChapterId=`（返回 stale 范围与 jobId）**尚未实现**：当前只有 stale 标记与前端提示，无重建 job 端点。见 §9 模糊项。

## 7. 成本与迁移诊断接口

当前仓库只提供后端接口/CLI，未发现对应的独立桌面页面；因此这些接口不能计入“页面已覆盖”，需要后续页面需求单独补充。

| 功能               | 接口                                                  | 请求参数             | 主要响应字段                                                                                                                                                                                                                                                                 |
| ------------------ | ----------------------------------------------------- | -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 章节成本报表       | `GET /projects/:projectId/cost-report?chapterNumber=` | 可选 `chapterNumber` | `reports[].inputTokens`、`outputTokens`、`cacheReadTokens`、`cacheWriteTokens`、`systemChars`、`sharedChars`、`identityChars`、`suffixChars`、`dynamicChars`、`toolSchemaChars`、`arrangedEntitiesChars`、`agentShares`、`firstCallInputTokens`、`firstCallCacheReadTokens`、`toolSchemaShareOfInputPct`、`roundTripTotal`、`cacheReadRatio` |
| Agent 成本占比     | `GET /projects/:projectId/agent-cost-share`           | 无                   | `shares[].agentType`、`calls`、`inputTokens`、`cacheReadTokens`、`costUnits`、`sharePct`                                                                                                                                                                                     |
| 相邻章 shared 重复 | `GET /projects/:projectId/shared-overlap`             | 无                   | 全量/仅实体档案两个口径的 `p50`/`p75`/`max` 重复率、`topSections[].sectionId/count`（如 chapter-info / story-ledger / arranged-entities）                                                                                                                                     |
| V2 双写对账        | `GET /projects/:projectId/v2-reconciliation`          | 无                   | `chapterRange`、`wordBudget{matched,mismatched,items[]}`、`sceneCount{matched,mismatched,items[]}`、`eventSceneFields{totalEvents,eventsWithSceneId}`、`overallMatched`                                                                                                      |
| 上下文预览         | `GET /projects/:projectId/context-preview?chapterNumber=&agentType=&mode=` | 必填 `chapterNumber` | 各 section 字符数/来源标记/前 200 字预览（见 §4.2）                                                                                                                                                                                                                          |

成本字符统计只对实际发送的 `user-message` 计量；历史日志同时存在 `task-input` 时，报表优先使用 `user-message`，不重复计入。`rollbackVerified` 只有实际回滚演练才能为 `true`，只读对账函数不得硬编码为 `true`。

## 8. 外部系统引用

本轮仓库内未发现与上述页面或接口对应的原型图片、Markdown 图片引用或新的外部系统接入项。LLM/Provider 调用属于既有 Agent 基础设施，不作为本轮新增接口的外部系统条目；如需求补充外部系统，必须在本节增加系统名、调用方向、鉴权方式、超时/重试和失败映射。

与本轮相关的既有基础设施页面不因本轮字段/接口变更而成为新增接口：缓存诊断（`cache-monitor-panel` 的 `cache-diagnostics`/`cache-layer-report`）、一致性审计（`consistency-audit-panel` 的 `consistency-report`）、相似实体扫描（`similarity-scan-panel` 的 SSE `entities/similarity-scan` 与 `entities/merge-similarity`）、参考小说分析（`reference-analysis` 面板的 `reference-sources` 系列）、创作流程 SSE（`create-flow`/`ai-arrange`/`reverse-arrange`/checkpoint decision/群聊）均为既有能力，不在此清单展开。

## 9. 当前模糊项与待确认决策

1. `asOfRevision` 当前定义为源事实指纹校验，不是历史投影快照查询；若产品要求真正读取历史版本，需要新增持久化投影版本或重建任务契约。
2. `projectionLag` 当前同步构建恒为 `0`；引入 outbox/异步投影后必须改为提交 revision 与投影 revision 的差值或可解释时间量。
3. `rollbackVerified` 只有实际回滚演练才能置为 `true`；只读对账函数不得硬编码为 `true`。
4. TX3 已写入同库 `novel_projection_outbox` 的 `pending` 事件；当前矩阵同步读取账本，不依赖消费者。若后续切换异步投影，必须实现幂等消费、重试和 `projectionLag` 的真实计算后才可使用该事件驱动投影。
5. 中间章重写的重建 job 端点 `POST /projects/:id/rebuild?fromChapterId=`（剧情重构 §9 契约）尚未实现；当前仅有 stale 标记（§6.1）与前端提示，需后端任务契约（stale 范围、jobId、顺序重放期间禁止跨章叠加当前快照）落地后才可交付“从本章开始重建”。
6. `p3/context-report` 与 `context-preview` 目前由看板页/CLI 调用，无独立产品页面需求；若需从产品入口触达，需补充页面需求。
