# 缓存与监控一体化设计规格

> 日期：2026-08-15
> 参考项目：DeepSeek Harness（`deepseek-ai/deepseek-harness`）
> 实施范围：`apps/agent-server` 后端与 `apps/desktop` 桌面端
> 状态：设计已确认，等待进入实现阶段

## 1. 目标

吸收 DeepSeek Harness 在能力分层、事件驱动观测、可重建请求和统一 TokenUsage 方面的设计，完善本项目的模型调用缓存与监控链路。

本次交付必须同时满足：

1. 同一项目、同一章节的 Director、Writer、Reviewer 等调用使用稳定的缓存域。
2. 仅向支持的 Provider 发送对应的缓存参数。
3. 统一记录 Provider、模型、缓存键、请求指纹、Token、耗时、状态和错误码。
4. 后端提供项目级、章节级、Agent 级监控 API。
5. 桌面端展示实际缓存读取率、缓存前缀覆盖率、Token、成本、耗时和错误状态。
6. 区分真正的缓存未命中与 Provider 未上报缓存数据。
7. 定时刷新保留现有数据，不造成监控面板闪烁。

## 2. 非目标

- 不引入 Cordis 或 DeepSeek Harness 运行时。
- 不替换现有 SQLite、Agent 日志、Usage Ledger 和缓存分层诊断实现。
- 不把 API Key、完整请求头或敏感凭据写入遥测数据。
- 不在本次范围内建设通用 OpenTelemetry 导出器。
- 不改造盲审、非标准聊天等明确不使用缓存 Skill 的路径。

## 3. 参考设计与本项目映射

| DeepSeek Harness 设计 | 本项目落点 |
| --- | --- |
| 能力通过插件和事件接入 | 复用现有 PluginManager、AgentCallLogger、UsageLedger 和 NovelServices |
| `SessionEvent` 是可重放事实源 | 以 `novel_agent_logs` 作为当前领域调用事实源，补充可重建请求元数据 |
| 独立 `TokenUsage` | 统一使用现有 input/output/cache read/cache write 字段，并在聚合层计算衍生指标 |
| `agent/*`、`llm/*`、`session/*` 事件 | 增加领域内的模型调用遥测事件接口，不侵入 Agent 编排状态机 |
| Provider 错误归一化 | 复用 `llm-error-policy`，在遥测中记录稳定的 `errorCode` |
| 请求头可重建 | 记录请求指纹、缓存键和提示词分层字符数，不重复保存大文本 |

## 4. 后端设计

### 4.1 统一模型调用遥测

新增 `apps/agent-server/src/core/observability/model-call-telemetry.ts`，提供纯类型和纯函数：

```ts
export type CacheProtocol = 'anthropic-cache-control' | 'openai-prompt-cache-key' | 'automatic-prefix' | 'none' | 'unknown'
export type TelemetryDataQuality = 'complete' | 'partial' | 'no_data'
export type CacheVerdict = 'healthy' | 'partial' | 'miss' | 'no_data'

export interface ModelCallTelemetry {
  provider: string
  model: string
  agentType: string
  phase: string
  cacheKey: string | null
  cacheProtocol: CacheProtocol
  requestFingerprint: string
  systemPromptChars: number
  sharedContextChars: number
  identityChars: number
  dynamicPromptChars: number
  inputTokens: number | null
  outputTokens: number | null
  cacheReadTokens: number | null
  cacheWriteTokens: number | null
  durationMs: number
  status: 'success' | 'error' | 'timeout' | 'cancelled'
  errorCode: string | null
  dataQuality: TelemetryDataQuality
}
```

规则：

- `requestFingerprint` 对规范化后的请求分层内容计算稳定摘要，不保存原文。
- `cacheReadTokens`、`cacheWriteTokens` 缺失时使用 `null`，不使用 `0` 冒充未命中。
- `cacheHitRate` 只有存在有效输入和缓存读取数据时才计算。
- `prefixCoverage` 使用 `cache-layer-diagnostics` 的字符/token 自校准逻辑。
- 不同 Provider 的缓存协议由 `cache-control-support.ts` 统一判断。

### 4.2 数据持久化

在 `novel_agent_logs` 增加迁移 `100_add_model_call_telemetry`，新增字段：

- `cache_key TEXT`
- `cache_protocol TEXT`
- `request_fingerprint TEXT`
- `cacheable_prefix_chars INTEGER`
- `data_quality TEXT`
- `error_code TEXT`

现有 Token、Provider、模型、耗时和提示词体积字段继续复用。历史记录的新字段为空时，API 返回 `null` 或 `no_data`。

不新增重复的 Token 表。项目级报表从 `novel_agent_logs` 聚合，普通聊天或非小说调用继续由 `UsageLedger` 记录。

### 4.3 API

在现有 `observability-routes.ts` 增加：

- `GET /projects/:projectId/observability/overview`
- `GET /projects/:projectId/observability/cache`
- `GET /projects/:projectId/observability/agents`
- `GET /projects/:projectId/observability/timeline`

所有接口支持：

- `from`、`to` 时间范围。
- 可选 `chapterNumber`。
- 可选 `agentType`。
- 有界 `limit`，最大值为 500。
- 项目不存在时返回现有 `NOT_FOUND` 错误。

`overview` 至少返回：调用次数、成功率、失败率、超时率、输入/输出/缓存读/缓存写 Token、缓存读取率、平均耗时、总成本和数据质量。

`cache` 至少返回：总体覆盖率、按章节诊断、按 Agent 诊断、缓存协议分布、缓存键稳定性、`healthy`/`partial`/`miss`/`no_data` 结论和诊断提示。

`agents` 返回每个 Agent 的调用次数、成功率、Token、缓存读取率、平均耗时、成本和最近错误。

`timeline` 返回按时间排序的调用摘要，不返回完整提示词正文。

### 4.4 缓存策略

- DeepSeek 和其他自动前缀 Provider 保持字符串消息结构，不注入 Anthropic `cache_control`。
- Anthropic 原生或明确兼容的路由使用 `cache_control`。
- OpenAI 官方端点使用由 `buildPromptCacheKey` 生成的稳定 `prompt_cache_key`。
- 小说标准流程使用 `novel:${projectId}:${chapterNumber}` 作为共享缓存域。
- STATIC、shared、identity 按稳定性排列在动态任务之前。
- 动态任务、工具结果、实时用户指令不得进入共享缓存前缀。
- Skill 正文和薄身份壳保持确定性顺序，项目或 SQLite 自定义 Prompt 继续走既有回退路径。

## 5. 桌面端设计

### 5.1 API 类型

在 `apps/desktop/src/renderer/src/api/novel-client.ts` 增加后端四组响应类型和请求函数。所有衍生指标直接使用后端结果，前端不再自行推导不同口径的缓存命中率。

### 5.2 缓存面板

扩展现有 `cache-monitor-panel.tsx`：

- 保留 STATIC / SEMI / DYNAMIC 哈希诊断。
- 增加实际缓存读取率和前缀覆盖率。
- 展示 Provider、模型、缓存协议和缓存键。
- `healthy` 显示绿色，`partial` 显示黄色，`miss` 显示红色，`no_data` 显示灰色。
- 哈希稳定只标识提示词稳定，不再单独标识为缓存命中。
- 轮询刷新时保留旧数据，仅更新数据时间和刷新状态。

### 5.3 Usage 总览

扩展现有 `UsageOverview`：

- 总输入 Token。
- 总输出 Token。
- 缓存读取 Token。
- 缓存写入 Token。
- 实际缓存读取率。
- 缓存前缀覆盖率。
- 总成本。
- 调用次数。
- 平均耗时。
- 成功率。

### 5.4 Agent 日志

扩展现有 `agent-log-panel.tsx`：

- 列表行显示 Provider、模型、缓存协议、缓存读取率和状态。
- 详情显示请求指纹、缓存键、前缀覆盖率、错误码、数据质量和 Skill 名称。
- 无数据时显示「数据不足」，不显示为 `0%`。
- 保留现有 STATIC、SEMI、DYNAMIC、工具和结果展开能力。

### 5.5 趋势区域

在已有 Novel 监控区域中增加轻量趋势视图，使用项目现有图表依赖：

- 按时间的调用量和 Token。
- 按 Agent 的缓存覆盖率。
- 按章节的缓存诊断。
- 错误状态分布。

## 6. 错误与兼容

- 观测写入失败不得阻断模型调用主流程，记录服务日志并返回主流程结果。
- Provider 未提供 Token 时，指标状态为 `no_data`。
- Provider 返回错误时，保留稳定错误码和原始错误短摘要；不保存凭据和完整敏感响应。
- 旧数据库自动通过迁移补齐字段。
- 旧日志在新 UI 中可正常展示，缺失字段使用空状态。
- API 请求失败时，桌面端保留上一次成功数据，并显示非阻塞错误提示。

## 7. 测试与验收

后端测试：

- 遥测规范化和请求指纹稳定性。
- 缓存协议判定和稳定缓存键。
- 命中率、前缀覆盖率和 `no_data`。
- 错误码归一化。
- 迁移后新旧日志读写。
- 四组观测 API 的过滤、聚合和空数据。

桌面端测试：

- 四组 API 数据渲染。
- 缓存状态和数据质量显示。
- 定时刷新不清空旧数据。
- API 失败保留旧数据。
- Token 和缓存指标使用后端口径。
- 旧日志字段缺失时的兼容显示。
