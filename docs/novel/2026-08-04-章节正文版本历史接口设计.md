# 章节正文版本历史接口设计

## 1. 页面与用户路径

页面：小说工作区“章节正文版本历史”弹框。

用户路径：章节正文编辑器底部点击“历史版本” → 选择版本查看正文 → 可勾选两个版本查看 Diff → 点击“应用到正文” → 二次确认 → 当前草稿先落库 → 服务端保存当前正文快照并应用目标版本 → 编辑器和小说数据 store 同步最新正文。

应用失败或当前草稿保存失败时不得修改正文。应用成功后弹框保持打开并刷新版本列表，最新当前版本默认选中。

## 2. 独立接口清单

| 功能 | 方法 | 路径 | 请求或查询 | 页面字段与响应 | 复用说明 |
| --- | --- | --- | --- | --- | --- |
| 版本列表 | GET | `/chapters/:id/versions` | `id` 为章节 ID | `id/sequence/phase/agentType/trigger/wordCount/wordCountDelta/createdAt/isCurrent` | 列表、当前版本标识和应用目标选择共用 |
| 版本详情 | GET | `/chapters/:id/versions/:versionId` | 章节 ID、版本 ID | 列表字段及 `chapterId/projectId/content` | 正文预览与应用确认共用 |
| 版本对比 | GET | `/chapters/:id/versions/diff` | `from/to` | `fromVersionId/toVersionId/fromSequence/toSequence/segments/stats` | 两个 checkbox 选择后复用既有段落 Diff |
| 手动快照 | POST | `/chapters/:id/versions` | `trigger` | 新版本详情 | 空版本列表也允许创建首个快照 |
| 应用前保存当前草稿 | PATCH | `/chapters/:id` | `content` | 最新章节 `content/wordCount/updatedAt` | 复用正文编辑器的防抖保存接口；保存失败时阻止应用 |
| 应用版本到正文 | POST | `/chapters/:id/versions/:versionId/rollback` | 章节 ID、目标版本 ID | `success/savedVersionId/currentContent/currentWordCount` | 复用既有安全回滚接口；前端以 `applyChapterVersion` 语义封装，不新增重复服务端接口 |

## 3. 数据与外部引用核对

- 页面展示字段已覆盖版本列表、详情、Diff 统计与片段、应用结果。
- 应用前由正文编辑器复用既有 `PATCH /chapters/:id` 保存未落库草稿。
- 应用接口在事务内先创建 `rollback_pre` 快照，再写入目标正文并创建 `rollback_applied` 版本，因此不会删除历史记录。
- 本页面不引用外部系统。

## 4. 模糊项与术语

- 用户界面统一使用“应用版本”，强调把所选内容写入当前正文。
- 服务端兼容路径和持久化 phase 仍使用 `rollback` 命名；两者是同一安全操作，不应再新增 `/apply` 重复接口。
- “当前版本”以列表响应 `isCurrent` 为准；历史版本应用后生成新的当前版本，而不是修改旧版本记录。
