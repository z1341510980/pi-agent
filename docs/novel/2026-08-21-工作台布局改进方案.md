# 小说工作台布局改进方案

> 日期：2026-08-21
> 范围：`apps/desktop/src/renderer/src/components/novel/**`、`apps/desktop/src/renderer/src/stores/novel-workspace-layout-store.ts`
> 状态：提案（未实施）
> 关联：`docs/novel/2026-08-15-对话式创作形态实现计划.md`、`docs/novel/matrix-redesign-prototype.html`

## 1. 背景与目标

当前工作台采用「顶栏 + 左侧栏 + 主内容区（四选一布局）+ 右侧栏（四 Tab）」结构。功能上已经完整，但实际使用中暴露出两类问题：

- **不好看**：横条堆叠过多、右栏内容挤压、各视图 chrome 高度不一致，切换布局时纵向跳动。
- **不合理**：同一能力多处入口且行为不一致、审校类功能撕裂在两个互斥视图里、模式维度过多导致心智负担高。

本方案目标：

1. 每个能力只有一个权威入口，行为一致。
2. 主内容区 chrome 收敛到最多一条工具条，图例/辅助控件浮层化。
3. 右栏四种 Tab 内容各自获得合适的宽度与会话空间。
4. 不改变任何业务逻辑与数据流，纯 UI 层改动优先。

## 3. 设计原则

1. **单一权威入口**：每个能力一个主入口；确需捷径时，捷径必须复用同一路径（如 `runChapterTask`），不允许第二份实现。
2. **chrome 上限一条**：主内容区任何视图下，内容之上最多一条工具条；辅助信息（图例、统计、性能提示）一律浮层化。
3. **右栏按内容适配**：宽度随 Tab 内容类型记忆，而不是全局一刀切。
4. **模式可发现**：所有用户可达的模式必须在界面上有可见入口，斜杠命令只是加速器而非唯一通道。
5. **先视觉后结构**：P0 只动 className/渲染顺序，不动数据流；结构性重构放 P2。

## 4. 目标布局

```
┌────────────────────────────────────────────────────────────────────┐
│ header 48px：返回 | 项目名        布局Segmented + 模型      右栏开关 │
├──────────┬────────────────────────────────────────────┬────────────┤
│ 左侧栏    │ 主内容区（内容之上最多一条工具条）           │ 右栏        │
│ 180-360  │                                            │ 宽度按Tab   │
│          │ text:     [编辑器单行chrome]                │ 分别记忆    │
│ 项目列表  │           编辑区                            │            │
│ 大纲树    │ text-timeline: [编辑器] / [矩阵] 上下分屏    │ ┌────────┐ │
│          │                                            │ │会话     │ │
│          │ timeline: [MatrixToolbar 单行]              │ │详情     │ │
│          │           矩阵（图例=底部浮层pill）          │ │设置     │ │
│          │                                            │ │审计     │ │
│          │ graph:    画布（工具条=左上浮层）             │ │审校(新) │ │
│          │                                            │ └────────┘ │
└──────────┴────────────────────────────────────────────┴────────────┘
```

关键变化：

- 矩阵从「4 条横条」减到「1 条工具条 + 底部图例浮层」。
- graph 从「顶栏 + 独立工具条」变为「顶栏 + 画布内浮动工具条」，消除切换跳动。
- 编辑器从 102px chrome 减到约 70px（header 与格式工具条合并为一行）。
- 右栏新增「审校」Tab，聚合五个审校面板；扫描结果不再劫持 Tab 栏。

## 5. 改进项明细

### 5.1 P0 —— 视觉与空间整理（不动数据流）

#### P0-1 编辑器 chrome 合并

- 现状：header（章节导航）与 toolbar（格式按钮）两行共 70px，footer 另占 32px。
- 方案：
  - header 与 toolbar 合并为一行：左侧「上一章 | CH.xx 徽章 | 下一章」，右侧格式按钮组（小尺寸）。
  - footer 保留保存状态 + 字数，保存/反推/历史版本按钮移入合并行的右侧或溢出菜单。
  - 修复 `.cce-body { min-height: 240px }`：改为 `min-height: 0` + flex 撑满，消除 120px 容器下的裁剪冲突。
- 涉及：`chapter-content-editor.tsx`、`chapter-content-editor.css`
- 验收：分屏模式拖到最小高度 120px 时无裁剪、无双重滚动；chrome 总高 ≤ 72px。

#### P0-2 矩阵横条收敛

- 现状：MatrixToolbar + 第二排按钮行 + 图例条 + 搜索框，最多 4 条。
- 方案：
  - 第二排 4 个按钮（剧情轨道/待审实体/待确认事件/批注）在 P0 先收进 MatrixToolbar 右侧的「审校 ▾」下拉菜单（面板组件与状态不动，只改触发方式）。
  - MatrixLegend 折叠态保留为细条；展开态的搜索框并入折叠条行内（搜索框与图例同行，不再独占一行）。
- 涉及：`matrix-workspace.tsx:1483-1556`、`matrix-toolbar.tsx`、`matrix-legend.tsx`
- 验收：矩阵内容之上只剩 1 条 h-10 工具条 + 可折叠图例细条；四个审校面板仍可打开。

#### P0-3 graph 工具条浮层化

- 现状：NovelToolbar 是顶栏之下的独立横条，切布局时插入/拔出引起整页纵向跳动。
- 方案：NovelToolbar 渲染为画布容器内左上角浮动卡片（`absolute top-2 left-2`，圆角 + 阴影 + 半透明背景），随画布出现消失，不影响文档流。ReactFlow Controls 与 MiniMap 位置相应避让。
- 涉及：`novel-workspace.tsx:1162-1168`、`novel-canvas.tsx`、`novel-toolbar.tsx`
- 验收：text ↔ graph 来回切换时主内容区高度零变化；工具条不遮挡节点拖拽热区。

#### P0-4 会话面板 header 单行化

- 现状：模式行 + 状态卡两行约 70px。
- 方案：
  - 合并为单行：左侧流程模式（见 P1-3 的全量 Segmented），右侧章节徽章 + 状态文字（进度 truncate 保留）。
  - 状态卡背景样式取消，降为行内元素，节省约 36px 给消息流。
- 涉及：`novel-conversation-panel.tsx:1384-1457`
- 验收：header 高度 ≤ 40px；运行中锁定行为不变。

#### P0-5 错误卡归位消息流

- 现状：错误卡是消息流的兄弟 shrink-0 块，长质量门失败卡（含 4 按钮）压缩消息可视区。
- 方案：错误卡作为消息流的最后一个 sticky 元素渲染（`sticky bottom-0`），跟随滚动但始终可见；空闲态错误同样处理。
- 涉及：`novel-conversation-panel.tsx:1459-1510`
- 验收：长错误出现时消息区可视行数不少于 3 行；错误卡始终可见可操作。

### 5.2 P1 —— 信息架构收敛（改行为，需回归测试）

#### P1-1 审校中心（新右栏 Tab）

- 现状：五个审校面板（待审实体/剧情轨道/修订/待确认事件/批注）分散挂在画布与矩阵两个互斥视图的工具栏里，同类功能被视图切换撕裂（A2）。
- 方案：
  - 右栏新增第 5 个 Tab「审校」（icon: ShieldCheck，原审计 Tab 更名为「体检」或并入审校作为其一）。
  - 审校 Tab 内部用左侧图标导航或子 Segmented 切换五个面板；面板组件原样复用，只迁移挂载点。
  - Tab 标题带全局待办角标（待确认事件数 + 待审实体数之和）。
  - 矩阵/画布工具栏中的对应按钮改为「跳转到审校 Tab + 定位到子面板」，或直接删除。
- 涉及：`novel-workspace.tsx`（RIGHT_PANEL_OPTIONS）、`novel-workspace-layout-store.ts`（RightPanelView 增加 `'review'`，持久化版本 v3→v4）、`novel-toolbar.tsx`、`matrix-workspace.tsx`
- 验收：任一布局模式下都能到达全部五个审校面板；旧 localStorage 布局偏好迁移后不丢失。

#### P1-2 入口语义统一

逐项消除 A 组问题：

| 项 | 决策 |
|---|---|
| 反推实体（A1） | 编辑器按钮改为调用 workspace 的 `runChapterTask({kind:'reverse'})`，删除 `chapter-content-editor.tsx:224-266` 的本地 SSE 实现；创作运行中自动切到会话 Tab 看进度 |
| 导出/导入（A3） | 顶栏保留导出；导入移入顶栏（或项目设置面板）；画布工具栏的导入/导出删除 |
| 缩放（A4） | 画布：删除 toolbar 缩放组，保留 ReactFlow Controls + Ctrl 滚轮；矩阵：保留 toolbar 缩放组（Ctrl 滚轮保留） |

- 涉及：`chapter-content-editor.tsx`、`novel-toolbar.tsx`、`matrix-toolbar.tsx`、`novel-workspace.tsx`
- 验收：反推从编辑器触发后，会话面板出现与 Tab 触发一致的流程消息流；全仓库 `window.history.back()` 在 novel 组件中清零。

#### P1-3 流程模式全量可达

- 现状：空闲时只有反推/编排两个按钮，工作流/群聊只能靠斜杠命令发现（B2）。
- 方案：header 单行里的流程选择器显示全部 4 项（工作流/群聊/反推/编排）。340px 宽度下单行 4 个短标签（写/群聊/反推/编排）可行；若挤，用「流程 ▾」下拉。斜杠命令保留为加速器。
- 涉及：`novel-conversation-panel.tsx:112,1384-1425`
- 验收：不输入任何命令即可触达全部四种流程；`PRIMARY_FLOW_TABS` 注释与实现一致。

#### P1-4 右栏宽度按 Tab 记忆

- 现状：四种 Tab 共用一个 `rightPanelWidth`（C1）。
- 方案：layout store 升 v4，`rightPanelWidths: Record<RightPanelView, number>`；默认 conversation 340 / detail 420 / settings 380 / audit 400 / review 400。拖拽分隔条时写入当前 Tab 的宽度。
- 涉及：`novel-workspace-layout-store.ts`、`novel-workspace.tsx:1332-1347`
- 验收：切 Tab 时宽度平滑过渡且各自记忆；v3 用户升级后 conversation/detail 宽度沿用旧值。

## 7. 风险与兼容

1. **localStorage 迁移**：RightPanelView 扩展 + 宽度记录需要 persist version v3→v4，必须显式 `migrate`（现有代码已有先例与注释，见 `novel-workspace-layout-store.ts:120-171`），否则用户布局偏好会被整体丢弃。
2. **引导 tour 失效**：`onboarding/tours/novel-tour.ts` 引用了 `data-tour` 锚点（如 `right-tab-conversation`、`matrix-toolbar`），P0/P1 移动这些锚点后需同步更新 tour 步骤。
3. **测试快照**：`novel-conversation-panel.test.tsx`、`novel-workspace-command.test.tsx` 等断言了 DOM 结构，P0-4/P0-5 会破坏快照，需同步更新。
