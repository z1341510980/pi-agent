# 参考小说分析功能接口设计

> 日期：2026-08-03  
> 状态：接口设计稿，待评审  
> 源需求：[2026-08-03-参考小说分析功能设计.md](./2026-08-03-参考小说分析功能设计.md)  
> 接口前缀：`/api/plugins/novel`  
> 目标：把源需求中的导入、分析、审核、验证、模板复用和章节生成闭环落实为页面级接口，并保证原文数据与当前小说事实隔离。

## 一、设计基线与约束

### 1.1 状态说明

| 状态 | 含义                                     |
| ---- | ---------------------------------------- |
| 新增 | 本功能需要新增的接口                     |
| 扩展 | 在现有接口请求、响应或内部处理上增加字段 |
| 复用 | 已有接口保持语义不变，页面直接调用       |
| 后续 | 不属于第一版，但预留资源和命名           |

### 1.2 现有接口基线

代码基线中已经存在以下能力，本文按实际路径复用：

| 能力                             | 现有接口或模块                                                                          |
| -------------------------------- | --------------------------------------------------------------------------------------- |
| Provider、模型、上下文窗口和价格 | `GET /api/providers`；响应中的 `models[].cost/contextWindow/maxTokens`                  |
| Provider 远端模型发现            | `GET /api/providers/:id/models`                                                         |
| 当前项目文风档案                 | `GET/PUT /projects/:projectId/writing-style-profile`                                    |

| 本地质量统计                     | 文风指纹、`prose-quality-evaluator`、`cliche-scanner` 中的中性统计能力                  |

### 1.3 通用协议

- 普通 JSON 接口继续使用 `{ ok, data, traceId }`；失败使用统一错误码，并在 `details` 中返回字段级校验错误。
- 创建分析、生成示例、发布模板等请求接收 `Idempotency-Key`，重复提交返回同一个资源。
- 更新 section、finding、template version 和 binding 时提交 `version`；版本不一致返回 `409 VERSION_CONFLICT`。
- 列表统一支持 `cursor/limit`，默认 `limit=50`，最大 `200`。
- 时间使用 ISO 8601；字符偏移统一指向标准化文本，采用 UTF-16 code unit 还是 Unicode code point 必须在实现前固定，不能混用。
- 原文接口只返回最短必要预览；列表、日志、SSE 和错误信息不得返回完整原文、完整 Prompt 或本地绝对路径。
- 所有项目级接口校验 `projectId` 所有权；模板接口只返回当前用户的私人模板。
- `DELETE` 原文前先查询影响，再提交影响摘要 hash，防止页面基于过期信息执行删除。

## 二、页面接口清单

### 2.1 P1 参考源管理页

用户路径：进入小说项目 → 参考小说分析 → 浏览参考源 → 新建导入、继续未完成分析、查看结果或删除原文。

| 状态 | 方法   | 路径                                           | 请求或查询                                    | 主要响应与页面字段                                                                                                                                                                                                                                       |
| ---- | ------ | ---------------------------------------------- | --------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 新增 | GET    | `/projects/:projectId/reference-sources`       | `status/inputKind/hasSourceText/cursor/limit` | `id/displayName/inputKind/fileFormat/fileSize/encoding/language/parseStatus/chapterCount/sceneCount/characterCount/estimatedTokens/latestRun/latestProfileVersion/retentionPolicy/sourceTextState/createdAt/updatedAt`                                   |
| 新增 | GET    | `/reference-sources/:sourceId`                 | -                                             | 完整 `ReferenceSourceDetail`、质量摘要、最新分析、关联 profile/template、权利确认和删除状态                                                                                                                                                              |
| 新增 | GET    | `/reference-sources/:sourceId/deletion-impact` | `mode=sourceText/all`                         | 将失效的证据数量、运行中任务、保留的 profile/template、项目绑定、最小审计记录和 `impactHash`                                                                                                                                                             |
| 新增 | DELETE | `/reference-sources/:sourceId`                 | `mode`、`impactHash`、`confirmation`          | `deletedSourceText/deletedSections/deletedEvidence/deletedAnalysis/retainedProfiles/retainedTemplates/auditRecordId/deletedAt`                                                                                                                           |
| 新增 | GET    | `/reference-source-records/:recordId`          | -                                             | `originalSourceId/sourceName/fileFormat/fileSize/contentHash/encoding/characterCount/estimatedTokens/providerId/modelId/analyzedAt/resultVersion/rightsConfirmation/deleteMode/deletedAt/deleteStatus/sourceTextCleared/evidenceCleared`；不含原文与路径 |

删除规则：

- `mode=sourceText` 仅删除原文、section 文本和可逆证据片段；保留抽象统计、profile、已确认模板、HMAC 指纹和最小审计记录。
- `mode=all` 仅在没有运行中任务且用户明确二次确认时删除该 source 的分析草稿；已被其他项目绑定的已发布模板不能级联删除，只解除来源可核验状态。
- 原文删除后，P5 的证据接口返回 `410 SOURCE_TEXT_DELETED`，页面仍可展示证据偏移、内容 hash 和“无法重新核验”状态。

### 2.2 P2 导入确认与费用预估页

用户路径（阶段 1）：参考源管理页点击导入 → 选择或拖放 TXT/Markdown，或切换到粘贴文本 → 执行编码预检 → 查看格式、大小、字符数、Token、编码置信度、预计章节和 hash → 确认编码、原文保留方式与文本权利 → 生成本地报告 → 进入文本质量确认。

页面交互约束：导入页以“选择文本 → 预检确认 → 本地分析”三步呈现；预检完成后锁定本次 source 输入，避免修改输入后继续使用旧预检结果。Provider、模型、上下文窗口和费用估算放在“模型上下文与费用预估（仅展示）”区域，阶段 1 可选查看且不得触发 LLM 请求。预检、费用估算和本地解析分别维护请求状态与失败重试，不能用一个共享 loading 误导用户；关闭页面或切换导航前必须提示未保存的输入或确认项。

| 状态 | 方法  | 路径                                               | 请求或查询                                                                                                                                      | 主要响应与页面字段                                                                                                                                                         |
| ---- | ----- | -------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 复用 | GET   | `/api/providers`                                   | -                                                                                                                                               | `provider id/name`、`models[].id/name/cost/contextWindow/maxTokens`；不返回 API Key                                                                                        |
| 复用 | GET   | `/api/providers/default`                           | -                                                                                                                                               | 默认 `provider id`                                                                                                                                                         |
| 新增 | POST  | `/projects/:projectId/reference-sources/preflight` | `multipart(file, displayName)`、桌面安全桥接 JSON `inputKind=file/fileName/bytesBase64/displayName`，或 JSON `inputKind=paste/displayName/text` | `sourceDraftId/inputKind/displayName/fileFormat/fileSize/detectedEncoding/encodingConfidence/language/characterCount/estimatedChapterCount/contentHash/warnings/supported` |
| 新增 | PATCH | `/reference-sources/:sourceId/import-options`      | `encoding/retentionPolicy/rightsConfirmed/rightsStatement/cloudAnalysisConfirmed`、`version`                                                    | 更新后的导入选项和重新解码后的字符、章节、乱码告警摘要                                                                                                                     |
| 新增 | POST  | `/reference-sources/:sourceId/analysis-estimate`   | `providerId/modelId/selectedSectionIds?`、`outputReserveTokens/safetyMarginTokens`                                                              | `ReferenceTokenBudgetEstimate`；P2 未选 section 时估算全量，供用户提前判断是否要缩小范围                                                                                   |
| 新增 | POST  | `/reference-sources/:sourceId/parse`               | `version`                                                                                                                                       | 只执行本地解码、标准化和分段；返回 `parseStatus/qualityReportId/chapterCount/sceneCount/excludedCandidates/nextPage`                                                       |

`preflight` 必须做到：

- 第一版只接受 TXT、Markdown 和粘贴文本；检测 UTF-8、UTF-8 BOM、GBK、GB18030。
- 无法可靠识别编码时返回 `ENCODING_CONFIRMATION_REQUIRED`，禁止把乱码提交给 LLM。
- 清理控制字符、重复页眉页脚、站点水印和广告时只生成候选，P3 确认前不做不可逆删除。
- 不静默截断。`parse` 是本地操作，即使全量预算超限也允许进入 P3 选择部分章节；真正启动分析时按最终 section 集合重新估算并执行硬限制。
- 上传和粘贴均计算原始 hash 与标准化 hash；服务端和日志不得保存本地文件路径。

### 2.3 P3 文本质量与章节划分确认页

用户路径（阶段 1）：导入确认完成 → 在“质量概览”查看编码、乱码、标准化和清理候选 → 切换“章节边界” → 优先筛选低置信度章节 → 展开章节、预览边界上下文、调整偏移或排除区域并逐项保存 → 查看本地报告。阶段 2 才在最终范围和费用再次确认后启动语义分析。

页面交互约束：“质量概览”和“章节边界”是 P3 同一页面内的独立视图，复用本节接口清单。章节列表默认摘要展示标题、类型、字符数、Token、置信度和纳入状态；低置信度或带警告的章节默认展开，并提供“全部章节/需确认”筛选。原始 `start/end` 仅在展开编辑区出现，保存前校验整数、顺序、重叠和版本；存在未保存章节修改时，切换筛选、页面或关闭弹框必须二次确认。

| 状态 | 方法  | 路径                                             | 请求或查询                                                                                    | 主要响应与页面字段                                                                                                                                                                                      |
| ---- | ----- | ------------------------------------------------ | --------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 新增 | GET   | `/reference-sources/:sourceId/quality-report`    | -                                                                                             | `encoding/encodingConfidence/mojibakeWarnings/controlCharacterCount/duplicateHeaderFooterCount/watermarkCandidates/adCandidates/chapterBoundaryConfidence/sceneBoundaryConfidence/normalizationChanges` |
| 新增 | GET   | `/reference-sources/:sourceId/sections`          | `type/included/parentId/cursor/limit`                                                         | `id/parentId/type/order/title/start/end/characterCount/estimatedTokens/boundaryConfidence/contentHash/included/exclusionReason/warnings/version`                                                        |
| 新增 | GET   | `/reference-sources/:sourceId/text-preview`      | `sectionId/start/end/contextChars`                                                            | 标准化偏移、最多 2000 字符的最短必要文本、`truncated`、相邻边界、已排除区标记；仅本机受控读取                                                                                                           |
| 新增 | PATCH | `/reference-sections/:sectionId`                 | `title/start/end/included/exclusionReason`、`version`                                         | 更新后的 section、受影响的父子 section 和 token 汇总                                                                                                                                                    |

| 新增 | POST  | `/reference-sources/:sourceId/analysis-estimate` | 最终 `providerId/modelId/selectedSectionIds/outputReserveTokens/safetyMarginTokens`           | 按确认范围生成最终估算和 `estimateHash`；任一 section 修改后旧 hash 失效                                                                                                                                |

页面必须展示源需求列出的全部确认字段：章节边界、场景数量、目录/广告/后记排除项、编码和乱码告警、低置信度边界、抽样正文，以及纳入分析的字符数和 token。启动分析时服务端重新校验 `estimateHash + includedSectionIds + sourceVersion`；不一致返回 `409 ANALYSIS_ESTIMATE_STALE`。

用户路径：文本质量确认页完成本地解析 → 查看可复现的全文统计与数据质量警告 → 返回章节范围继续调整。该子页不调用 LLM，不创建 profile/template，不写入当前项目人物、剧情、账本或 Prompt。

| ---- | ---- | ---------------------------------------------------- | ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

阶段枚举固定为：

```text

### 3.6 汇总档案

`ReferenceNovelProfile` 保留源需求中的完整四类结构：

- `styleSpirit.worldview`：`humanNature/fate/success/power/morality/emotion/conflict/growth/worldAttitude`。源需求的 TypeScript 示例遗漏了成功观、冲突观和世界态度，接口以第三章维度表为完整口径。
- `styleSpirit.valueExpression`：`directCommentary/characterChoice/consequenceDriven/contrastDriven/ironyDriven/ambiguity`。
- `styleSpirit.authorTemperament`：`restraint/warmth/sharpness/solemnity/romanticism/cynicism/compassion/humor`。
- `styleSpirit.narrativeTone`：`conciseOrExpansive/directOrIndirect/colloquialOrLiterary/explicitOrImplicit/narratorPresence`。
- `proseCraft`：感官比例、主体化视角、生理-情绪-认知链、紧张感知顺序、悬念后置、爽点详略和期待兑现规律。
- `narrativePower`：重点选择、详略分配、描写穿透力、场面掌控、信息密度和情绪累积释放。
- `pacing`：场景、章节、全书三级张力/信息/情绪/动作/对话曲线，事件距离、概率和章节类型模式。
- `storyElements`：功能角色、目标、障碍、代价、选择、行动、后果、揭示、秘密、线索、伏笔、回收、反转、误解、承诺、悬念债务、关系/身份/状态变化、世界规则、资源和期限的抽象模式；不含参考源专名和具体剧情。
- `chapterPatterns/findings/safetyReport/coverage`：章节类型规则、全部发现、安全报告和三类覆盖率。

这些字段由 `GET /reference-profiles/:profileId` 一次返回；P5 可按标签懒加载 findings，但不能用四套相互独立的 profile 接口制造多个真相源。

      estimatedCost?: number
    }
  | { type: 'warning'; eventId: string; code: string; message: string }
  | { type: 'checkpoint'; eventId: string; checkpointId: string; resumable: boolean }
  | { type: 'result'; eventId: string; resourceId: string; resourceType: 'profile' | 'validation' }
  | { type: 'error'; eventId: string; code: string; message: string; retryable: boolean }
```

事件沿用现有 AG-UI/SSE envelope、15 秒心跳和 trace/run ID，但分析 run 是持久资源，断线不等于自动取消。页面使用 `Last-Event-ID` 重连；只有用户显式点击取消才调用 cancel 接口。

## 四、用户操作路径与接口序列

### 4.1 首次导入并生成模板

1. P1 调用 source 列表；用户点击导入。
2. P2 调用 `preflight`，再读取 `/api/providers`，选择 provider/model。
3. P2 更新编码、权利确认和原文保留策略，调用全量 `analysis-estimate`；超限时提示用户稍后选择部分章节，但不阻断本地解析。
4. P2 调用 `parse`，进入 P3。
5. P3 读取质量报告、sections 和最短预览；用户调整边界或排除范围，再按最终 section 集合重新调用 `analysis-estimate`。
6. P3 使用最终 `estimateHash` 创建 analysis run；预算不通过、估算过期或未确认高费用时均阻断；P4 订阅 SSE。
7. 取消时调用 cancel；失败时按 checkpoint retry/resume；完成后拿到 profileId。
8. P5 读取四类 profile/findings，逐项审核并查看证据与反例。
9. P6 生成 application preview，处理冲突后创建 template draft。
10. P7 使用原创同场景生成基准和模板示例，整改规则并重新生成。
11. 用户接受验证后发布私人模板版本，再在 P8 绑定到一个或多个项目。

### 4.2 章节生成时采用或关闭模板

1. P9 读取项目 bindings，明确展示本次开关、模板名、固定版本和章节类型。
2. 用户每次提交前调用 resolve，确认有效规则、hash、Prompt 增量和冲突。
3. 调用扩展后的 create-flow；后端记录实际模板版本和各 Agent 注入情况。
4. 关闭开关时传 `enabled=false`；后端不得读取或注入模板。
5. 生成完成后读取 reference usage 和 similarity report；重写章节生成新的使用记录。

### 4.3 删除原文但保留模板

1. P1 调用 deletion-impact，展示证据失效、保留模板和绑定项目。
2. 用户确认后提交 `mode=sourceText + impactHash`。
3. 服务端清除原文、section 文本和可逆证据，创建最小审计记录。
4. 已发布模板继续工作；P5 标记原文已删除，P9 相似度报告标记能力降级。

### 4.4 模板版本调整与回滚

1. P8 比较两个版本。
2. 编辑或 rollback 都创建新草稿版本。
3. 规则变化后重新执行 P7；通过后发布新版本。
4. 已绑定项目继续使用旧固定版本，直到用户显式更新 binding。

## 六、接口复用合理性检查

- Provider 和模型信息直接复用 `/api/providers`，不新增“参考分析模型列表”接口，避免价格和上下文窗口出现第二个配置源。
- 分析进度、同场景生成和章节创作复用同一 AG-UI/SSE envelope、心跳、usage 和错误结构；分析 run 因需要断点恢复，新增持久事件读取，而不是强行复用断线即结束的 POST 长连接。
- 四类分析结果共用 profile/findings/reviews 接口，用 `category` 区分；不为文风、文笔、笔力和节奏各建 CRUD。
- 模板全局版本和项目 binding 分离：模板保存可复用规则，binding 只保存项目选择与覆盖项，防止同一模板被某项目修改后影响其他项目。
- 章节生成继续扩展现有 `create-flow`，不新增“参考模板创作流”；这样检查点、取消、日志和章节版本仍只有一套流程。
- 当前文风档案接口只作为预览基线。参考 profile/template 不直接写入 `NovelWritingStyleProfile`，避免丢失证据、来源、版本和 Agent 范围。
- Entity Generator 的 Session、JSON 修复和进度机制可抽取复用，但其项目实体写库逻辑不得调用。
- 当前角色、冲突、伏笔、地点、物品和故事账本接口不参与参考源写入；参考小说的专名和具体剧情没有映射到这些接口。
- 现有 `NovelSimilarityScanner` 解决项目实体的语义去重，不能直接承担参考原文短语与节拍相似度检查；只可复用 LLM Session 和报告展示模式。
- 同场景基准与模板示例共用一个 validation run 和固定事实 hash，不建立两套独立生成接口，保证可比较性。
- 手工审核和批量审核共用同一 review schema、版本校验和安全扫描服务，避免批量操作绕过规则。

## 八、待确认与模糊项

以下问题必须在实现相应接口前固定；当前接口通过显式字段保留决策空间，不静默假设：

1. **生成开关默认值**：项目 `defaultEnabled` 是默认关闭，还是沿用用户上次选择；建议第一版默认关闭，且每次提交仍显示最终值。
2. **测试场景来源**：同场景验证默认由系统生成原创场景，还是要求用户输入；接口支持 `system/user/currentProject` 三类，产品需选默认值。
3. **思想硬规则冲突**：与主题、大纲和人物设定的冲突检测采用纯规则、LLM 还是两阶段；阻断阈值未定义。
4. **Provider 元数据缺失**：无法读取上下文、tokenizer 或价格时的保守默认值、币种和是否允许继续尚未确定。
5. **模板导出**：原文删除后是否允许导出模板，以及导出包是否必须附来源删除和版权风险声明。
6. **总量限制含义**：源需求一方面要求整份文本不超过“有效输入预算”，另一方面采用分层 Map-Reduce；需确认限制是单次调用上限、单个 chunk 上限，还是用户确认的整次分析费用上限。
7. **分析覆盖策略**：源需求写“不能逐章全部调用 LLM”，但没有定义抽样比例、抽样方法和最低覆盖率；`semanticCoveragePolicy` 需要产品默认值。
8. **费用重估**：重试、断点恢复和用户整改会追加调用；追加费用达到什么阈值需要再次确认尚未定义。
9. **原文保留默认值**：正文激活后立即删除、延迟删除还是只提示用户删除；`delete_after_activation` 的具体触发时机未定。
10. **HMAC 密钥生命周期**：密钥轮换、设备迁移和备份后，旧指纹是否继续可用尚未定义。
11. **安全与相似度阈值**：连续短语长度、8-12 字符 n-gram 阈值、LCS 阈值、节拍相似度和专名阻断规则需要基准集校准。
12. **证据最短片段长度**：版权安全与可审核性之间的最大字符数未定义。
13. **模板发布语义**：源需求同时出现“激活 profile”和“保存模板”；本文采用“profile 审核 → 模板草稿 → 验证 → 发布 → 绑定”，需产品确认不保留绕过模板的直接激活路径。
14. **项目绑定升级**：模板发布新版本后是仅提示、允许批量升级，还是逐项目确认；本文明确禁止静默升级。
15. **彻底删除边界**：已写入章节历史审计的模板版本能否彻底删除；建议只允许归档，并永久保留不可变最小使用记录。
16. **并发限制**：同一 source、项目和 provider 可同时运行多少分析和验证任务，尚未定义。
17. **页面原型缺失**：源需求目录中没有与本功能对应的原型图片；本文已覆盖文字描述中的页面字段，但无法校验原型中可能存在的额外控件和字段。
18. **未来格式质量门槛**：EPUB、DOCX、HTML、PDF、OCR 的解析失败和 OCR 置信度阈值留到阶段 4。
19. **多参考源融合**：来源权重、共同规律阈值和单一来源降权公式留到阶段 5；第一版 resolve 明确只接收一个模板版本。
20. **源需求数据结构不一致**：第三章思想维度包含成功观、冲突观和世界态度，但 `ReferenceStyleSpiritProfile.worldview` 示例未列出；第七章要求故事要素分析，但 `ReferenceNovelProfile` 示例没有 `storyElements`。本文已按功能需求补齐，需产品确认后同步回源需求文档。
21. **验收与使用记录缺表**：源需求要求保存同场景验收记录并冻结历史章节实际模板版本，但建议表结构没有对应实体；本文补充 validation run、template usage 和持久 SSE event 三张表，需数据库评审确认保留期与清理策略。
22. **章节类型采用三维组合**：源需求中的八个页面标签不是新的单值词表。当前代码已有六类 `ChapterPositioning`（`high_pressure/advancement/cultivation/relationship/low_pressure/information`）、八类 `ChapterRhythm` 和十四类 `NarrativeTaskType`，本文直接组合三者表达适用范围。实现前仍需固定一章存在多个叙事任务时的规则匹配优先级，以及用户手动覆盖与 Director 自动分类的优先级。
23. **本地导入保护阈值**：阶段 1 为避免 Base64 请求与 SQLite 原文存储耗尽本机资源，暂以 20 MiB 原始文件作为硬上限；该值及超限后的分片导入方案仍需产品确认。
24. **高费用二次确认阈值**：产品尚未定义按金额或 Token 触发强制二次确认的阈值。阶段 1 仅返回并展示费用区间，不创建 LLM 分析 run；阶段 2 启用云端分析前必须固定阈值与币种规则。

## 九、第一版接口验收条件

1. P1-P9 每个页面都有独立接口清单，页面展示字段均能从响应中直接取得或由明确的静态枚举提供。
2. TXT、Markdown、粘贴文本和四类编码可完成 preflight；乱码、超限和未确认高费用均无法启动分析。
3. 任一分析 run 可取消；成功 chunk 可在失败后从 checkpoint 恢复，且实际 token 与费用可审计。
4. 文风、文笔、笔力、节奏均有 finding、证据、反例、置信度、覆盖率和逐项审核动作。
5. 未通过安全检查和同场景验收的模板版本无法发布，未发布或未绑定的版本无法用于章节生成。
6. 关闭“采用参考模板”后，Director、Writer、Reviser、Reviewer、Memory 均不收到模板；开启后 Memory 仍不接收。
7. 原文、专名、具体剧情和精确章节序列不会写入当前小说实体、故事账本或生成 Prompt。
8. 原文删除后已发布模板继续可用，证据读取明确失效，最小审计记录不含原文和本地路径。
9. 历史章节能查询当时实际使用的模板版本和 hash，不受模板后续编辑、发布或回滚影响。
10. 需求覆盖矩阵、外部系统、复用检查和模糊项在评审中逐项签字，不以“实现时再决定”替代产品决策。
