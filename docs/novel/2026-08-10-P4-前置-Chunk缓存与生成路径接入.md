## 1. 已完成：chunk-cache.ts

### §5.6 原样实现

```ts
interface ContextChunkCacheEntry {
  projectId: string
  chunkId: string
  versionKey: string
  content: string
  contentHash: string
  updatedAt: number
}

computeChunkVersionKey(source: ChunkVersionSource): string  // sha256 前 16 位
// ChunkVersionSource = { projectUpdatedAt, entityRevisionIds, latestMemoryEventId, styleProfileVersion }
```

### 能力

- `ChunkCache`：进程级内存 Map，key = `projectId:chunkId:versionKey:contentHash`，含 hit/miss/entries 统计与 `clearProject`；内容哈希用于隔离章节、角色和工具权限导致的同版本不同 chunk
- `buildWithChunkCache`：§5.6 复用循环——build 时逐 chunk 查缓存，命中直接用（省构建），未命中重建并 put，返回 `fromCache` 标记 + hit/miss 计数
- 失效语义：versionKey 任一分量变化 → miss（§5.6 五个失效入口统一表现为输入变化）

### 测试（6/6）

- versionKey 确定性 + 顺序无关 + 任一分量变化即失效
- ChunkCache hit/miss 统计 + clearProject 只清该项目
- 复用循环：首轮全 miss 并缓存 → 同 key 二轮全命中；输入变化（模拟 Memory applyChanges）→ 全 miss

## 1.5 已完成：versionKey 数据源（P4 接入第 1 步）

- `ChunkVersionSourceProvider`：最小依赖接口（duck typing，NovelStore 天然满足）
- `buildChunkVersionSource(provider, projectId)`：聚合 versionKey 输入——
  - projectUpdatedAt ← project.updatedAt
  - entityRevisionIds ← **表级 max(updatedAt) 指纹**（characters/conflicts/foreshadows/clues/factions/locations/items/world-elements/relationships），
    比逐实体 id 紧凑且满足失效语义（任一实体修订 → 表指纹变 → key 变）
  - latestMemoryEventId ← memoryStore.listStoryEvents 末项 id（可选）
  - styleProfileVersion ← writing_style_profiles.updatedAt
- 测试 +3（9/9 总计）：空表不产生指纹 / 实体修订变化 key 失效 + 未变稳定 / 账本事件与文风档案变化 key 失效
