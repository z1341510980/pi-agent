# 保留 project_id / chapter_number 等冗余标识

日期：2026-08-11 状态：已采纳

背景：规范化审查中多次提议删除实体表与日志表上的 project_id、chapter_number 冗余列（可由外键推导）。

决策：凡满足以下任一用途的冗余标识一律保留——项目隔离、日志检索、覆盖索引、审计恢复、减少高频 join。删除字段必须同时证明：无独立查询用途、无隔离/审计用途、可安全推导、漂移风险低于查询收益。

理由：novel_agent_logs 等审计表需要不依赖 join 的按项目/章节检索；覆盖索引避免回表；数据修复场景下冗余列是恢复锚点。推导链条越长，故障面越大。

反方观点：冗余列存在漂移风险。以"单一权威写入点 + 定期对账任务"（§13.5）控制，而不是删除列。
