# 场景级生成默认不启用，仅在 A/B 达标后灰度

日期：2026-08-11 状态：已采纳

背景：Writer 整章长上下文成本偏高，存在"改为逐场景生成以降低单次上下文"的提议。

决策：场景级生成不作为默认工作流；ChapterScenePlan 先作为前置数据结构落地（影子写 + 对账），场景级 Writer 由 sceneLevelWriter flag 保护，仅在满足启用条件任意三项（sceneCount≥3、实体≥8、超预算、历史均值≥15k token、已有批准计划、缓存命中率低）且 Control/Treatment 对比达标（总 token 降≥20%、质量与人工采用率不降）时灰度。

理由：场景级生成降低单次上下文的同时增加调用次数、system/tool 固定开销、场景衔接缺陷、Weaver 合并成本与中断恢复复杂度；未经 P0 测量无法确认 Writer 整章是主要成本来源。

反方观点：等数据再开会拖慢降本节奏。以 P0 测量基线（已交付）先行回答"token 花在哪"，数据成立即启动灰度，避免的是盲目切换而非延迟优化。
