# pi-agent 直播话术流程

> 主题：用 AI 写一本网文小说是什么体验
> 平台：抖音 | 时长：90 分钟 | 目标：演示系统 + 引流创作者

---

## 一、直播概览

| 项目 | 内容 |
|------|------|
| 直播主题 | 用 AI 写一本网文小说是什么体验 |
| 副标题 | 我让 5 个 AI Agent 像编辑部一样协作写小说 |
| 平台 | 抖音 |
| 时长 | 90 分钟 |
| 目标受众 | 网文作者、小说创作者、AI 工具爱好者、副业探索者 |
| 核心目标 | 演示 pi-agent 多 Agent 协作创作系统，引流创作者进私域 |
| 转化路径 | 直播间 → 粉丝群 → 体验 Demo → 私域转化 |
| 核心钩子 | "5 个 AI Agent 分工写作，导演/写手/审稿/修订/记忆，像真编辑部" |
| 演示案例 | 内置小说《叶明远传》第 3 章（修真穿越题材） |

### 直播人设

- 身份：独立开发者 / AI 工具研究者
- 调性：技术专业 + 创作热情，不卖弄、不喊麦
- 语言风格：口齿清楚、节奏明快、少用术语、多用比喻
- 禁忌：不贬低传统创作、不吹"AI 替代作家"、不承诺收益

### 演示前置条件（开播前 30 分钟必须确认）

- [ ] pi-agent 桌面端已启动，演示项目《叶明远传》已加载
- [ ] 矩阵视图能正常打开，第 3 章已写好可随时展示
- [ ] 创建流程能完整跑通（Director → Writer → Reviewer → Reviser），提前预跑一次
- [ ] LLM API key 已配置，余额充足
- [ ] OBS 场景切换正常（人脸 / 屏幕录屏 / 双画面）
- [ ] 福袋、群口令、关注卡片已设置
- [ ] 备用视频：录一段 3 分钟的演示回放，防现场翻车

## 三、详细话术脚本

### 环节 1：暖场留人（00:00-05:00）

**目标**：3 秒留人、30 秒讲清今天讲什么、发福袋锁人。

**开场白（开播第 1 句话）**

> "别划走，我接下来 90 分钟，给你看一个真东西：5 个 AI Agent 像编辑部一样，自己分工、自己写、自己审、自己改，写出了一本修真小说。"
>
> "我是 [昵称]，独立开发者，今天不卖课、不带货，就给你看一个我自己做的 AI 小说创作系统，叫 pi-agent。"

**价值承诺（10 秒讲清今天听什么）**

> "今天你能看到三件事：
> 第一，AI 是怎么像真编辑部一样协作写小说的；
> 第二，我现场跑一遍，从大纲到成章，全流程不藏；
> 第三，我已经写好的第 3 章，咱们一起读一段，看 AI 写得行不行。"

**留人钩子 + 福袋**

> "现在直播间人不多，我先发个福袋。福袋口令我设成'AI 写小说'，抢完别走，10 分钟后我直接开始演示。"
>
> "如果你是写网文的、写小说的、或者想搞副业的，扣个 1 我看看，我重点讲给你听。"

**动作清单**

- 发福袋，口令"AI 写小说"
- 念 ID 欢迎进直播间的人（前 3 个真人）
- 切到屏幕共享画面，露出 pi-agent 桌面端

---

### 环节 2：痛点共鸣（05:00-15:00）

**目标**：让目标受众（网文作者/创作者）觉得"这说的就是我"。

**灵魂三问开场**

> "我先问你三个问题，你心里默默回答：
> 第一，你是不是写小说写到一半，卡在那里，不知道下一章该让谁出场、该埋什么伏笔？
> 第二，你是不是写到 20 万字以后，前面埋的伏笔自己都忘了，读者一提醒你才想起来？
> 第三，你是不是写完一章，自己读着别扭，但又说不出来哪里不对？"

**拆痛点（每个痛点配一个比喻）**

> "这三个问题，本质上是三件事：
> 一是节奏控制，写到中段节奏散了，读者跑路；
> 二是伏笔管理，前面埋的雷后面没收，读者骂街；
> 三是审稿盲区，自己写的自己看不出来毛病。
>
> 这三件事，传统作者是怎么解决的？要么靠责编，要么靠大纲党，要么硬憋。但责编不是人人有，大纲写了经常不跟，硬憋出来的东西读者不买账。"

**引出 pi-agent**

> "所以我就想，能不能让 AI 来当这个责编团队？
> 不是 ChatGPT 那种一问一答，而是真的有导演、有写手、有审稿、有修订、有记忆管理员，分工干活。
> 我花了半年做了一个系统，叫 pi-agent，今天第一次公开演示。"
>
> "切到电脑画面，我给你看它长什么样。"

**动作清单**

- 切屏幕共享
- 打开 pi-agent 桌面端，停留在工作台首页
- 弹幕引导："觉得痛点戳中的扣 1，没戳中的扣 2"

---

### 环节 3：系统揭秘（15:00-30:00）

**目标**：讲清 pi-agent 的核心架构，让用户理解"多 Agent 协作"为什么不一样。

**3.1 一句话讲清 pi-agent（2 分钟）**

> "pi-agent 不是又一个 AI 写作机器人。它是一个多 Agent 协作系统。
> 简单说，你给它一个小说大纲，它会自己拆解成章节，然后派 5 个 AI Agent 分工干活：
> - 导演 Agent：负责规划这一章写什么、节奏怎么走
> - 写手 Agent：负责把内容写出来
> - 审稿 Agent：负责挑毛病，节奏、人设、伏笔有没有问题
> - 修订 Agent：负责按审稿意见改稿
> - 记忆 Agent：负责记住所有角色、关系、伏笔，保证前后不穿帮
>
> 这 5 个 Agent，就像一个真的编辑部。你挂个总编的名，它们干活。"

**3.2 讲架构图（5 分钟）**

> "我给你看它的架构。"
>
> （切到 pi-agent 工作台，打开一个小说项目，展示界面）
>
> "左边是大纲树，全书大纲、卷纲、章纲三层。你写小说之前，先在这里把骨架搭好。
> 中间是矩阵视图，这是 pi-agent 最有意思的地方。横轴是章节，纵轴是角色、伏笔、冲突、信息差。你能一眼看到：第 3 章谁出场、哪个伏笔在哪埋的、什么时候回收。
> 右边是创作面板，Agent 就在这里跑。"

**3.3 讲多 Agent 协作流程（5 分钟）**

> "我现在点一下'开始创作第 4 章'，你看会发生什么。"
>
> （演示创建流程启动，但不真跑完整流程，先讲流程）
>
> "第一步，导演 Agent 上场。它会读大纲、读记忆库，给你规划这一章的节奏：开篇怎么进、中段怎么推、结尾怎么收。
> 它规划完，会停下来等你确认。这就是这个系统的关键设计：Checkpoint。AI 不替你做决定，关键节点你来拍板。
>
> 你点'通过'之后，写手 Agent 上场，按导演的规划把章节写出来。
> 写完，审稿 Agent 上场，挑毛病。
> 挑完，修订 Agent 上场，按意见改稿。
> 全程记忆 Agent 在后台默默记录：这一章谁出场了、谁和谁关系变了、哪个伏笔埋下了、哪个冲突升级了。下一章再写的时候，这些记忆会被注入回去，保证前后连贯。"

**3.4 讲差异化（3 分钟）**

> "市面上 AI 写作工具，要么是一键生成，写完你不知道改哪；要么是对话式，你问一句它答一句，没有全局观。
> pi-agent 不一样的地方就两点：
> 第一，多 Agent 协作，每个 Agent 只管自己的活，干完交棒，像流水线；
> 第二，矩阵视图，让 AI 的'记忆'变成你能看见的东西。伏笔埋在哪、什么时候收，一目了然。"

**互动引导**

> "听到这儿，觉得这个思路有意思的扣'有意思'，觉得没听懂的扣'没懂'，我再讲一遍。"

**动作清单**

- 打开小说项目，展示三栏布局
- 矩阵视图缩放演示，让角色/伏笔/冲突可见
- 鼠标停留在某个 Agent 节点，让用户看清面板

---

### 环节 4：实操演示（30:00-55:00）

**目标**：现场跑一遍创作流程，让用户看到"真的能跑出来"。

> "光说不练假把式。我现在现场跑一遍，从第 4 章大纲，到 Agent 出稿，全程不剪。"

**4.1 准备工作（2 分钟）**

> "我先打开第 4 章的章纲。你看，我之前写好的：'叶明远用电钻采石，效率暴增被工头赵岩察觉，夜里赵岩派心腹监视窝棚'。这就是这一章的统一起点，导演 Agent 必须严格遵循。"

**4.2 启动 Director（5 分钟）**

> "点开始创作。你看，导演 Agent 上场了。"
>
> （实时观察 Agent 输出，边看边解说）
>
> "它在读大纲、读记忆库。你看它读到了什么：叶明远是穿越者、有玉佩、会用《引气诀》、赵岩是工头多疑。
> 现在它在规划这一章的节奏：开篇接上一章的矿坑场景，中段推电钻采石的高效反差，结尾埋赵岩派心腹的暗线。
>
> 它规划完，停下来等我确认。这就是 Checkpoint。我可以读一遍它的规划，觉得 OK 就通过，觉得不对就让它重写。"

**4.3 Checkpoint 互动（5 分钟）**

> "咱们一起读一下导演的规划。"
>
> （读 Director 的输出）
>
> "你觉得这个规划行不行？行就扣 1，不行扣 2。
> 我觉得它的节奏把控挺准的，开篇接得稳，中段有冲突，结尾留钩子。我点'通过'。"

**4.4 Writer 出稿（8 分钟）**

> "通过之后，写手 Agent 上场了。你看它开始写。"
>
> （观察 Writer 流式输出）
>
> "它是流式输出的，一段一段往出写。你看它写的开篇：'叶明远握着玉佩靠在碎石后面'。这个开篇我挺喜欢，直接进场景，不绕。
>
> 等它写完，咱们看完整内容。"
>
> （等 Writer 完成，控制在 5-8 分钟。如果太慢，用预跑的版本切换）

**4.5 Reviewer 审稿（5 分钟）**

> "写完了。现在审稿 Agent 上场挑毛病。"
>
> （读 Reviewer 输出）
>
> "你看它挑了什么毛病：'电钻采石的效率描写过于顺利，缺少成本和风险，建议增加低频振动引发矿脉共振的细节'。
> 这个意见我服气。AI 写东西容易一路顺，审稿 Agent 自己能挑出来，挺好。"

**4.6 Reviser 改稿（5 分钟）**

> "修订 Agent 上场，按审稿意见改。"
>
> （观察改稿过程）
>
> "你看它加了一段：'低频振动顺着矿脉传导，从手指传到手腕'。这个细节加得对路，把风险埋进去了。"

**4.7 演示结束总结（2 分钟）**

> "从大纲到成稿，全程 20 分钟。中间我做了 1 次确认，剩下都是 Agent 自己协作。
> 这就是 pi-agent 的核心能力：你不用自己写，但你能掌控方向。"

**应急话术**

- 如果现场卡住 / 报错："你看，AI 也翻车。这就是 Checkpoint 的意义，AI 翻车你能拦。我先切到备用演示，你看预录的版本。"
- 如果 LLM 太慢："这个模型今天有点慢，咱们先看已经写好的第 3 章，等会儿回来看结果。"

### 环节 5：成果展示（55:00-70:00）

**目标**：拿出已写好的第 3 章正文，证明系统真能产出可读内容。

**5.1 切到第 3 章（2 分钟）**

> "刚才跑的是第 4 章的演示。现在我给你看一个已经写好的，第 3 章。这是我之前用 pi-agent 写的，一字没改。"

**5.2 现场读一段（5 分钟）**

> （打开 chapter_003.md，读开篇）
>
> "'叶明远握着玉佩靠在一块半人高的碎石后面，手指能感觉到玉佩在变温。从冰凉到温热，又从温热回冰凉，像一个在调试信号的对讲机。'
>
> 你听这个比喻。'调试信号的对讲机'。这是穿越者视角，玉佩在他眼里是通讯设备，不是法器。AI 抓住了主角的穿越者身份，没有写成传统修真。
>
> 往后看。'玉佩猛地烫了一下。不是温热，是烫。像是有人把烙铁贴在了掌心。'
> 这个'猛地烫了一下'就是钩子。读者会想知道：发生了什么？蓝星那边传了什么？"

**5.3 拆设计：伏笔 + 信息差（5 分钟）**

> "我切到矩阵视图，给你看这一章埋了什么。"
>
> （打开矩阵视图，定位第 3 章）
>
> "你看第 3 章这一列。
> 角色层：叶明远（主角）、赵岩（主对手）、心腹杂役（功能位：放大冲突）。
> 伏笔层：埋了 3 个。
>   - 玉佩空间通道（明写，物品类）
>   - 废弃矿道深处的回响（暗写，事件类）
>   - 镇魔石料表面浮现纹路（侧写，事件类）
> 冲突层：叶明远 vs 赵岩，从'察觉'升级到'派心腹监视'，推进模式是线性升级。
> 信息差：读者知道玉佩能传物、知道矿道有异响，但赵岩不知道。这个信息差就是后续张力的来源。"

**5.4 拆记忆系统（3 分钟）**

> "这些东西，AI 不是写完就忘。它全都记在记忆库里。
> 我打开记忆面板你看。"
>
> （打开记忆面板）
>
> "这一章触发了多少个记忆事件：character_change 3 条、relationship_change 1 条、foreshadow_change 3 条、conflict_change 1 条。
> 下一章再写的时候，这些记忆会被注入回去。所以 AI 不会忘记赵岩已经起疑，不会忘记矿道有回响。"

**互动引导**

> "觉得这个记忆系统有用的扣'有用'。我看看多少人想要这个。"

### 环节 6：互动答疑（70:00-80:00）

**目标**：建立信任，回答真实问题。

**引导话术**

> "剩下 20 分钟，回答问题。你想问什么随便扣，技术问题也行，小说创作问题也行。"

**预设问答（如果弹幕冷场，挑这些讲）**

**Q1：AI 写的小说能发表吗？会不会有版权问题？**

> "内容是你自己的，AI 只是工具。pi-agent 跑出来的稿子，你拿来发表没问题。但建议你自己过一遍，AI 写的东西，节奏和细节还是要人把控。"

**Q2：支持什么模型？要不要付费？**

> "支持 OpenAI、Anthropic、还有国产的几家。模型你自己配 API key，用多少花多少。pi-agent 本身是开源的，你愿意自己部署就自己部署。"

**Q3：能写其他题材吗？还是只能写修真？**

> "题材不限制。修真只是我演示用的。你写都市、写科幻、写悬疑都行，大纲你自己定，Agent 按你的大纲走。"

**Q4：跟 ChatGPT 写小说有什么区别？**

> "ChatGPT 是一次性生成，写完就完了，没有记忆，没有全局。pi-agent 是多 Agent 协作 + 跨章记忆 + 矩阵视图。你写到第 50 章，它还记得第 3 章埋的伏笔。这是本质区别。"

**Q5：普通人能用吗？要不要会编程？**

> "不用会编程。pi-agent 是桌面应用，下载下来就能用。今天直播完我会发体验入口，你自己跑一遍。"

**连麦规则**

- 优先连麦：扣"网文作者"的真实用户
- 连麦不超过 2 分钟，引导回主流程
- 黑粉 / 引战：礼貌下麦，不纠缠

---

### 环节 7：转化收尾（80:00-90:00）

**目标**：把直播间的人引流到私域。

**7.1 价值回顾（2 分钟）**

> "今天 80 分钟，你看到了什么：
> 5 个 AI Agent 像编辑部一样协作；
> 现场跑了一遍第 4 章创作；
> 拿出了写好的第 3 章，伏笔、信息差、冲突都能拆；
> 跨章记忆系统，AI 不会忘前面埋的雷。
> 这套东西，我自己用了半年，写了 3 万字。"

**7.2 发钩子（3 分钟）**

> "今天直播间能给的，就两样：
> 第一，pi-agent 的体验入口，你自己跑一遍；
> 第二，我整理了一份《AI 多 Agent 协作创作手册》，里面是 5 个 Agent 的提示词、矩阵视图的设计逻辑、还有我踩过的坑。
> 想要的，进粉丝群，群号 [口令]，口令就扣'AI 写小说'。"

**7.3 福袋收尾（2 分钟）**

## 六、应急话术

### 6.1 现场翻车 / Agent 报错

> "你看，AI 翻车了。这就是我做 Checkpoint 的原因：AI 不靠谱的时候，你能拦下来。我先切到预录的版本，你看完整流程，现场这个等会儿再跑。"

### 6.2 LLM 响应太慢

> "今天模型有点堵。咱们先看已经写好的第 3 章，等它跑完再回来看第 4 章。"

### 6.3 弹幕冷场

> "我看没人扣字，可能是我讲得太快了。我倒回 5 分钟，重新讲一遍这块。或者你直接问我，你想看哪部分？"

### 6.4 黑粉 / 引战

> "你说得有道理，AI 写作确实有局限。我演示完你再看，觉得不行那确实不行。咱们先看东西。"

### 6.5 直播间人数掉得快

> "刚进来的人别走，我马上要演示核心功能了，前面都是铺垫。"
>
> （发福袋 + 切到最吸引人的画面：矩阵视图或第 3 章正文）

## 七、转化路径设计

### 7.1 路径图

```
直播间观看
  ↓
扣"AI 写小说" / 抢福袋（建立互动）
  ↓
引导加粉丝群（群号口令）
  ↓
群内发 pi-agent 下载入口 + 创作手册
  ↓
群内答疑 + 案例分享（持续运营）
  ↓
私域转化（付费功能 / 进阶服务 / 社群）
```

### 7.2 群运营钩子

- 群公告放：下载入口 + 手册 + 演示视频
- 群规第一条：进群改昵称"笔名-题材"，方便匹配同好
- 每天发一条：当晚直播预告 + 前一天直播切片
- 每周发一次：用户案例 / 新功能更新

### 7.3 不做的事

- 不在直播间卖课（破坏信任）
- 不承诺收益（"用 AI 月入过万"这种话不说）
- 不贬低传统作者（"AI 替代作家"这种话不说）
- 不现场收钱（转化全走私域，不在直播间交易）

## 九、话术节奏要点（抖音适配）

| 原则 | 说明 |
|------|------|
| 3 秒留人 | 每个环节开场第一句话必须有钩子，不能"那个那个" |
| 90 秒切画面 | 抖音观众耐心短，每 90 秒切换一次画面（人脸/屏幕/矩阵视图/正文） |
| 多用比喻 | 技术名词（Agent/矩阵/伏笔）必须配一个生活化比喻 |
| 念弹幕 | 每 5 分钟念一条弹幕，让用户觉得被看见 |
| 不说"那个" | 口头禅用剪刀剪掉，影响完播 |
| 结尾留钩 | 每个环节结尾留一个"接下来"的悬念，不让人走 |
