# lengdu

一个面向中文小说的 Codex Skill：先完成小说，再将“作者侧校准”和“普通读者首读”分离，让作品在**看懂、流畅、好看**三项上接受独立检验。

这不是改写器、检测规避工具，也不承诺任何读者或检测结果。

## 核心流程

1. 作者在不追逐检测分数的前提下，完成一篇完整正文。
2. 一个不继承作者上下文的新 Agent 只检查两类风险：人物的重要变化是否缺少形成过程；正文是否把论证、揭晓和结算组织得过满。
3. 另一个全新的普通 Reader 按事件包顺序首读，只报告：当下是否看懂、是否顺着读下去、是否想继续。
4. 若修改，必须换新的 Reader 复核；不得把校准报告、作者意图或检测信息泄漏给 Reader。

可选的“检测兼容校准”只在用户明确提出时运行，并且必须以已通过读感的原稿为基线、另建平行候选、重新冷读与隐藏身份 A/B 比较。外部检测结果只是单篇实验事实，不能替代读感，也不能导出通过保证。

## 安装

将本目录放入 Codex 的 Skills 目录，例如：

```text
<CODEX_HOME>/skills/lengdu/
```

重启或刷新 Skills 后，在对话中请求 `$lengdu`，并给出题材、人物关系、事实约束、篇幅和不希望改动的内容。

示例：

```text
使用 $lengdu 写一篇 3000 字左右的现实题材短篇。
主角是一名替班护工；结尾必须保留她决定不再替人隐瞒的选择。
先完成正文，再按 Skill 的独立校准和 Reader 流程复核。
```

## 文件说明

- `SKILL.md`：运行入口、角色边界与完整闭环。
- `references/`：作家、作者侧校准者与 Reader 的档案、协议及针对性案例。
- `agents/openai.yaml`：Codex 的展示信息与默认提示词。

## 贡献

欢迎提交能改变规则的真实反例，尤其是：

- Reader 漏检的理解障碍；
- 把自然、好读文本误判为风险的反例；
- 新题材中的前向验证；
- 规则导致故事变钝、人物失真或流程过重的证据。

请不要提交未获授权的小说正文、个人信息、密钥、第三方检测报告或把检测分数当作质量结论的材料。
