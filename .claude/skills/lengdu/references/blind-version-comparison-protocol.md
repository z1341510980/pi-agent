# 隐藏版本A/B冷读协议

## 目的

比较两个已经完成的小说版本，判断其中一个是否以清楚、流畅或好看为代价。该比较只处理读者体验，不评价写作技巧、AI味、检测结果或修改是否“正确”。

## 实例与隔离

1. 使用两个从未读过任一版本的`fork_turns="none"`新Reader；不得复用普通单稿Reader、作者侧校准者、主作家或看过修改讨论的Agent。
2. 主Agent私下随机映射为文本X与文本Y。Reader只能收到本协议和两份正文，不能收到“原稿、改稿、检测稿、通过稿”等版本身份。
3. 不提供作者意图、大纲、用户反馈、修改目标、差异说明、外部报告、检测比例、怀疑位置或预期胜者。
4. Reader甲按X→Y阅读，Reader乙按Y→X阅读。两个Reader完成前不得交换报告。

如果无法建立两个零继承实例或交换顺序，只能标记“单Reader盲比降级”；不能声称已排除顺序效应。

## 阅读方式

- 每份正文只按原顺序读一遍，不做逐句技术分析。
- 两份正文较短时，一次只发送一份全文；较长时按相同的自然叙事原则分别切成顺序事件包，但必须完整读完一个版本后再读另一个版本，不得交错。
- 读第一份时记录自然发生的看懂、卡顿、扫读、兴趣上升或下降；读第二份时同样记录。后一个版本不能替前一个版本补写或解释。
- 两份都读完后才进行比较。允许对记得最清楚的段落作直接比较，但不要把任务升级成文学鉴赏或逻辑审计。
- 某一维度确实相当时可以判“持平”；两份都不成立时判“都不行”，不得为了完成任务强选胜者。

## 启动提示

```text
完整读取随附的《隐藏版本A/B冷读协议》，不要浏览任何相邻文件。你是本次干净比较Reader，不知道两个版本的身份、修改目标与预期答案。

我会按指定顺序发送文本X和文本Y。请像平时看同一个故事的两个版本一样各读一遍，保留第一次真实反应。收到【比较材料结束】前只回复“已读完当前材料，请继续”；收到结束标记后再严格按协议格式提交比较。不要评价AI味或检测结果，不提供改写。
```

## 输出格式

```markdown
## A/B最终读感
- 看懂与流畅：X更好 / Y更好 / 持平 / 都不行
- 开头牵引：X更好 / Y更好 / 持平 / 都不行
- 发现感或认识变化：X更好 / Y更好 / 持平 / 不适用 / 都不行
- 人物欲望、选择与代价：X更好 / Y更好 / 持平 / 都不行
- 高潮或关键转折：X更好 / Y更好 / 持平 / 都不行
- 情感余味：X更好 / Y更好 / 持平 / 都不行
- 继续阅读欲：X更好 / Y更好 / 持平 / 都不行
- 整体选择：X / Y / 持平 / 都不行
- 选择把握：高 / 中 / 低

## 我为什么这样选
- X最让我想继续的一处：引用短句并说明真实感受；没有写“无”。
- Y最让我想继续的一处：引用短句并说明真实感受；没有写“无”。
- X第一次掉速或变弱处：引用短句并说明；没有写“无”。
- Y第一次掉速或变弱处：引用短句并说明；没有写“无”。
- 决定整体选择的具体差异：只说读感，不猜作者目的。
```

## 主Agent合并规则

- 先检查两个Reader是否都遵守隔离、阅读顺序和输出要求，再解除X/Y映射。
- 若两名Reader在整体选择上同向，可把结果视为较强的版本比较证据；仍不能代表所有读者。
- 若结果相反，优先检查各自引用的真实读感和顺序效应，不用票数机械决定。必要时保留基线，或再启动一组交换顺序的新Reader。
- 任一版本单独未通过看懂、流畅、好看三项，不因A/B相对胜出而取得交付资格。
- 用户亲自比较后确认某版更弱，这是已经发生的真实读感，直接否决较弱候选；Reader漏检不能推翻用户体验。
