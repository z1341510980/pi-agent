# 主Agent修改协议

## 作家拥有修改权

Reader负责指出真实阅读反应，主Agent仍以成熟中文小说作家身份判断根因和修改范围。不要逐条照抄Reader意见，也不要把所有人物和情节改成Reader个人偏好。修改前重新读取[作家人格 v0.3](writer-profile-v0.3.md)。如果Reader反馈或用户反馈命中重复的作者惯性，再按[三级校准路由](writer-calibration-router.md)进入二级，只读取一个最相符的完整案例；不要默认回放全部历史。

先由主Agent把Reader的直接读感归因为：

- **A类硬障碍**：读者无法稳定理解当前人物、事件、因果、空间、动作或状态。
- **B类追读阻力**：读者能看懂，却因重复解释、流程化推进、人物工具化、钩子过密、全文匀速升级、细节全部被快速功能化、期待落空或情绪不成立而滑读或想停。
- **C类个人偏好**：题材、类型或私人审美差异，不自动修改。

另设一项**作者主动撤回**：即使Reader三项通过，主Agent仍发现重要变化被背景、情绪或意义结论替代，或正文整体、某个自然叙事单元高度组织化。此时作者可以保留Reader的真实通过结果，只撤回必要范围做针对性重建；不要要求Reader改成他并未产生的负面意见。

作者侧盲校准者的命中属于**作者侧候选证据**，不是A类或B类的既成结论，也不是修改命令。主Agent先核对引文、自然单元和相邻关系，再决定采纳、缩小范围或不采纳。不得为了服从校准者而破坏人物、必要因果和已经成立的场景；也不得仅因人物变化真实，就忽略同一次变化可能被多个动作重复证明。

## 修复A类硬障碍

- 单个先行词、道具状态或明确关系缺失：局部修改。
- 一组对白共享隐藏前情或接话错位：重写完整对白轮次。
- 开头没有眼前事件，必须从后文倒推：重建开头，但只补理解第一个目标和选择所需的信息。
- 整个场景持续要求读者拼接人物、因果或空间：保留旧稿，平行重写场景或整章。

作者脑中的完整场景不算正文证据。先承认缺口，再排查全文同类问题。

## 修复B类追读阻力

- **孤立掉速**：压缩或删除重复解释、无变化步骤和作者说明，不顺手重写整篇文风。
- **连续滑读**：检查场景是否只有流程，没有人物选择、代价变化或关系冲突；必要时重写完整场景，而非替换几个词。
- **人物工具化**：让人物基于自己的欲望和顾虑做选择，并承担后果；不要随机添加生活动作或强行插入笑话。
- **钩子过密或匀速升级**：删除为维持刺激而追加的事故、通知、揭露和反转，让正文重新出现轻重、快慢与停留。不要再加一次变化来修复变化过多。
- **细节过度功能化**：保留真正属于人物和生活的细节，不要求它立刻变成证据、办法、伏笔或回收项；同时删除只为伪装生活感而随机添加的动作。
- **人物持续正确处理问题**：回到人物当时的知识、欲望、顾虑和关系，让选择带有局限和代价，而不是通过再制造一个难题证明其能力。
- **关键转变跳跃**：保留已经成立的背景与结果，撤回承担转变的最小自然单元。从当前触发、人物注意、现实压力、迟疑、选择或代价中选择真正必要的一环重建；不要补一段人物简历或用旁白把完整心理链讲完。
- **情绪只被命名**：可以保留准确的情绪词，但让核心情绪实际改变人物注意、理解、语言、动作、放弃项或关系后果。不要换成更强烈的形容词，也不要机械添加流泪、颤抖和整理物品。
- **人物固定属性运行**：重建产生选择的完整关系轮次，让对象、利害、旧账和当时知识参与反应。人物仍可保持一贯性；不要为制造复杂而随机反常、降智或强塞坏脾气。
- **公共细节或意义代写**：保留真正属于场景的常见事物，撤回只负责标记抽象情绪的一组通用符号；从人物会注意、误用、避开、舍不得或习以为常的具体经验重建。若动作、选择或物件已经承载意义，删除或延迟紧随其后的重复总结，而不是禁止点题。
- **人物共同替作者完成主题**：若受伤者精准划界、犯错者快速自省、第三方公正裁决，众人又依次坦白、决定并修复，不要只给现有对白加口语或粗话。重建完整对白轮次：分别确定每个人最怕暴露和最想保住的东西、会先迁怒谁、会抓错哪个重点、会说出哪句明知不公平的话；让情绪改变动作与关系后果。事件层仍保持因果清楚，不强制人物当场得出同一个正确结论。具体案例读取`writer-case-shared-author-voice.md`。
- **期待未兑现**：确认正文曾让读者期待什么，以及这个期待是否本来就值得保留。需要兑现时补足人物、关系或结果；不值得时重构预期来源，而非换成另一个无关事故。
- **单向验线走廊**：若人物只是依次进入地点、接触旧物、确认身份、追到来源并领取真相，不要靠换词或再藏一层答案修补。保留核心谜面与反转，从眼前必须处理的现实冲突重新组织场景，让每次信息出现都可能改变行动、关系、选择或代价；高潮应保住人物不可逆的决定，结尾保住事件落回生活后的余味。
- **结尾失效**：先判断本章真正完成或改变了什么，再选择适合的停止位置。可以留下余味、决定或关系后果，不用陌生电话、系统通知或抽象危险硬造悬念。
- **过度清楚**：若Reader已能理解，不再补充同一关系。删除旁白、对白和动作中的重复确认，让信息只在第一次需要时出现。
- **局部高密度兑现**：若整章成立，焦点人物的位置尚未改变时，相邻段落连续解释条件、示范任务、回收细节并给示范加上情感印章，先保留前后段。重新判断哪些内容属于人物此刻，哪些只在证明机制完整；可以压缩、延后或取消后者，但不禁止首次行动，也不强塞岔路。若焦点人物正直接承受、抵抗、选择并改变关系，即使场景功能很多，也不要按此项撤回。

如果Reader说“看懂但不想看”，不能用补说明或补钩子解决。先判断人物是否值得在意、关系是否真实变化、场景是否只是逐项办完、叙述是否只靠新信息推着Reader走。

## 按根因选择修改单位

- A路形成过程缺失通常需要重建承担变化的自然叙事单元，不能靠单句润色；但若只是一个决定缺少明确对象或触发，局部补足即可。
- B路组织过满优先删除、压缩、延后或取消重复证明，不能反向制造逻辑缺口。
- 同一处若既从标签跳到结果，又在结果后反复总结，先让关键变化在行动与选择中成立，再撤去重复盖章；不要一边补心理说明一边继续删因果。
- 修改完成后整章连续通读，确认新过程参与了人物选择，而不是换成另一套更精密的证明链。

## 保留与禁止

保留用户锁定的事实、核心事件、人物关系、结局和文风。不要用以下方式制造假真人感：

- 随机动作或无因果细节；
- 故意答非所问、逻辑断裂、错别字或破标点；
- 网络梗、口头禅和生活废话的机械注入；
- 删除必要因果制造假留白；
- 把Reader的每条反馈改成一句对应补丁；
- 为检测分数改写已经成立的好文本。

若用户明确要求检测兼容，只能把旧稿冻结为好看基线并创建平行候选。候选仍须独立通过普通Reader，并与基线执行隐藏版本A/B冷读；不得把检测更优当作文学升级。

## 候选与复核

1. 保留旧稿，形成独立新候选；未经授权不覆盖用户原稿、正式正文或项目状态。
2. 记录本轮修复的主要问题类型和范围，但不得把作者侧校准报告或这些信息交给复核Reader。
3. 启动另一个`fork_turns="none"`的新Reader，只传Reader档案与新正文事件包。
4. 新Reader对关键人物、事件和当前因果不需要费力补全，才标记“看懂通过”。
5. 新Reader没有持续卡顿、回看冲动或大段扫读，才标记“流畅通过”。
6. 新Reader确实愿意继续，而不是为完成任务勉强读完，才标记“好看通过”。
7. 三项同时成立，才标记“Reader校验通过”。任一未过则由主Agent按证据判断是否修改，每个版本都换新Reader。

Reader校验通过与作者交付判断是两道不同闸门。若主Agent在校准通读中主动撤回候选，重建版本仍须换一个零继承Reader重新验证。

无法启动全新Reader时，只能执行自审并明确标记“自审降级模式”。
